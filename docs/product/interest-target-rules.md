# 관심 대상 선정과 공고 분류 규칙

2026-09-14 사용자 승인. 기준은 **사용자가 어디에 지원·참여하며 관계를 이어가려는가**이다.
게시자나 행사 운영자를 자동으로 즐겨찾기 대상으로 삼지 않는다.

## 서로 다른 네 가지 관계

| 데이터 | 역할 | 예 |
| --- | --- | --- |
| 조직의 `parentOrganizationId` | 조직·프로그램의 상위 관계 | 교육원 → 지속 대회 프로그램 |
| 공고의 `categoryPath` | 활동 분류 경로 | 채용 → 채용행사 |
| 공고의 `contexts` | 이번 행사와 관련된 학교·장소·대상 맥락 | 충북대학교 |
| 공고의 `favoriteOrganizationId` | 관계를 이어갈 관심 대상 ID | 한국농어촌공사 |

탐색 트리는 위 관계를 조합해서 표현할 수 있다. 기업 → 채용 → 채용행사 → 학교 → 공고라는
화면 경로가 학교의 실제 소속이 기업이라는 뜻은 아니다. `categoryPath`는 조직 ID를 담지 않는다.
학교 이름만으로 참가 자격을 제한하지 않는다. `event_context`는 포괄적 행사 맥락이며,
구체적인 장소·대상 학교·공동 운영 역할은 근거가 있을 때만 구별해 기록한다.

| 공고 | 관심 대상 | 분류 | 맥락 |
| --- | --- | --- | --- |
| 한국농어촌공사 채용설명회 | 한국농어촌공사 | 채용 → 채용행사 | 충북대학교 |
| DB손해보험 채용상담회 | DB손해보험 | 채용 → 채용행사 | 충북대학교 |
| 제2회 영남권 사이버 공격 방어 대회 | 영남권 사이버 공격 방어 대회 | 대회 | 별도 학교 맥락 없음 |

두 채용 공고의 대학일자리센터 `operator` 관계와 교육원의 `contact` 관계는 유지한다.
사용자가 예시로 쓴 연도·신입사원 표현을 원문 제목에 임의로 추가하지 않는다.
연도와 회차가 달라도 조직 ID는 유지하고 공고 ID는 따로 부여한다.

## 추출과 추론의 경계

1. 원문에서 기업·조직·프로그램과 역할을 추출하고 기존 조직 ID에 연결한다.
2. 관심 대상 후보인 `subject`와 공고 종류를 승인된 사례와 비교한다.
3. 후보와 적용 규칙이 각각 하나인 경우 대상과 분류를 제안한다.
4. 사람이 검토한 결과를 승인 사례로 기록하고 공통 샘플에 반영한다.

현재 구현은 **2~3번의 결정적 규칙 엔진과 승인 사례 저장**이다.
1번의 자연어 추출·동명이인 조직 식별은 수동 검토 단계이며, 크롤러나 LLM 추출기는 아직 없다.
원문 제목의 단어 일치만으로 기업을 고르거나 문의처를 관심 대상으로 승격하지 않는다.

규칙 파일: [target-rules.json](../../shared/contracts/activities/target-rules.json).
규칙은 공고 종류와 관심 대상 조직 ID의 조합, 활동 분류, 사용자가 승인한 공고·맥락을 보관한다.
관심 대상 후보가 여러 개거나 미등록 ID이거나 규칙이 충돌하면 자동으로 하나를 고르지 않는다.

| 반환 상태 | 의미 |
| --- | --- |
| `approved` | 공고 ID·관심 대상·공고 종류·학교 맥락이 등록된 승인 사례와 일치 |
| `suggested` | 같은 대상·공고 종류의 선례가 있으나 새 공고이거나 맥락이 달라 검토 필요 |
| `needs_review` | 대상 누락·복수 후보·알 수 없는 ID·선례 없음·규칙 충돌 등 |

반환값에는 후보 ID, 적용 규칙 ID, 이유를 포함한다. 승인 상태는 **관심 대상 매핑에만** 적용한다.
모집조건이나 마감 정보가 최신이라는 인증이 아니다. 새 공고는 같은 기업이어도 자동 승인하지 않는다.
도구는 제안 결과만 출력하며 입력이나 즐겨찾기를 수정하지 않는다.

```sh
npm run samples:infer
# 같은 catalog 형식의 새 공고 자료집을 검토할 때
npm run samples:infer -- /path/to/reviewed-catalog.json
npm test
```

샘플에는 `targetSelection`으로 사용자 승인과 기존 편집상 잠정 지정을 구별한다.
멘토링·학사 행정 공고는 기존 잠정 지정으로 남아 있으며, 추론 도구에서 선례가 없으면 검토를 요청한다.
개별 확정 시 규칙의 `approvedCases`와 샘플을 함께 갱신하고 동기화·검증한다.

## 앱 반영과 검증

두 앱은 확정된 샘플의 기업 ID를 저장한다. 반복 탭은 중복을 만들지 않고,
기업을 저장해도 행사 학교·운영부서·상위 조직을 자동으로 저장하지 않는다.
기존에 직접 저장된 대학일자리센터를 두 기업으로 강제 변환하지 않는다.
그 선택의 의도를 알 수 없으므로 기존 항목은 사용자가 삭제할 수 있도록 유지한다.

트리를 조합하는 탐색 UI와 운영자 검토 화면은 아직 구현하지 않았다.
공통 테스트는 선례 재사용, 복수 후보·규칙 충돌, 맥락 변경, 게시자·문의처 오인 방지를 검증한다.
