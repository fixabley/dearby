# 반복 01 — 공고 탐색에서 조직 즐겨찾기까지

2026-09-14. 목적은 관심 활동을 빠르게 훑고, 나중에 다시 볼 조직을 저장하는 경험을 확인하는 것이다.
사용자가 선택한 첫 흐름은 **카드 넘기기 → 더블탭 → 조직 즐겨찾기 목록**이다.

## 이번에 구현한 동작

- iOS SwiftUI와 Android Jetpack Compose에서 같은 공통 JSON을 읽는다.
- 검토한 실제 공고 5건 중 학사 행정 1건을 제외한 4건을 샘플 피드로 제공한다.
- 위아래로 넘기면 한 카드씩 이동한다. 카드 본문 더블탭 또는 명시적인 저장 버튼으로 조직을 저장한다.
- 저장은 조직 ID 기준으로 중복을 막는다. 다시 더블탭해도 해제하지 않으며, 목록의 삭제 동작으로 해제한다.
- 즐겨찾기에서 조직과 연결된 샘플 공고를 확인하고 공고 상세를 열 수 있다.
- 상세에는 대상, 필수 조건, 신청 기간, 단계별 활동 일정, 장소, 혜택, 확인할 정보와 원문 링크를 제공한다.
- 저장은 기기 내부에 유지된다. iOS는 UserDefaults, Android는 SharedPreferences를 사용한다.
- 빈 목록·샘플 로딩 실패 상태를 제공한다. 작은 화면에서는 카드 정보를 줄이고 상세에서 전체 내용을 보여준다.

## 검토 결과가 바꾼 설계

공고 게시자와 운영 조직, 소개 대상 기업이 달랐다. 세 역할을 별도 관계로 기록하고,
저장 버튼에는 실제 저장하는 조직명을 노출했다. 현재 한국농어촌공사·DB손해보험 공고는
사용자 승인에 따라 각각 한국농어촌공사와 DB손해보험을 저장한다. 대학일자리센터는
운영자로, 충북대학교는 행사 맥락으로 남기며 기업 하위 조직으로 만들지 않는다.

영남권 사이버 대회는 처음에는 저장 대상을 보류했으나 사용자 결정에 따라
교육원 → 대회 프로그램 → 제2회 공고로 연결하고, 대회 프로그램 저장을 활성화했다.
원문의 모집 대상이 충돌하는 멘토링 공고에는 확인 표시를 붙였다.
공고 정보의 불확실성은 사용자 프로필 부족과 구별한다.

원문의 제출 장소와 행사 장소, 신청 마감과 행사 종료를 분리했다.
CIEAT 마일리지는 외부 혜택으로 기록하며 Dearby 크레딧과 구분한다.
필드 사전과 공고별 근거는 [활동 공고 규격](activity-data-v1.md)을 따른다.

## 다음 사용감 검증에서 결정할 것

사용자 보완: 조직은 트리를 이룰 수 있고 한 조직에 여러 연도·회차의 공고가 연결된다.
`parentOrganizationId`를 공통 규격과 두 앱 모델에 추가하고, 충북대학교 하위 부서 샘플에 적용했다.
공고 저장 시 상위 조직으로 합치지 않으며 지정된 조직 ID를 유지한다.
트리 참조·순환 및 관심 대상 추론 검증을 포함한 공통 데이터 테스트는 13건이다.
트리 탐색 화면은 아직 구현하지 않았다. 상세 모델과 예시는 [규격서](activity-data-v1.md)를 따른다.

- 새 사례가 복수 관심 대상을 포함할 때 검토·선택 화면을 어떻게 제공할 것인가?
- 카드 요약만으로 관심을 정할 수 있는가? 대상·자격·일정·장소 중 먼저 보여줄 항목은 무엇인가?
- 세로 넘김, 더블탭 저장, 목록에서만 해제하는 방식이 자연스러운가?
- 원문 확인이 필요한 공고를 피드에 보일지, 검토 완료 후 보일지?

현재 피드는 고정된 검토 샘플이며 실제 개인화 추천·하루 한 번 갱신·자동 수집은 구현하지 않았다.
로그인, 기기 간 동기화, 추가 프로필 입력, Q&A·커피챗·크레딧은 후속 반복의 범위다.

관심 대상 선정 정책과 승인 사례 기반 제안 도구를 추가했다. [추론 규칙과 실행 방법](interest-target-rules.md)을 따른다.

## iOS 화면 반영

공고 카드에는 활동 분류와 행사 관련 학교를 표시한다. 상세에는 관심 조직과 저장 안내,
실제 상위 조직 경로, 활동 분류, 역할별 관련 기관, 회차를 구분한다.
즐겨찾기에는 저장한 조직의 상위 경로와 연결 공고 수, 각 공고의 분류·학교를 표시한다.
이전에 저장한 운영부서처럼 현재 연결된 공고가 없는 항목도 삭제하지 않고 빈 상태를 안내한다.
전체 조직을 접고 펼치는 트리 탐색 화면은 별도 후속 범위다.
Xcode 시뮬레이터 빌드·실행 및 카드 표시를 확인했고, Swift 검증에 기업과 학교의 분리,
대회 상위 경로 및 회차 디코딩을 추가했다.

## Android 화면 반영

iOS와 같은 공통 데이터를 사용해 카드의 분류·학교, 상세의 관심 조직·상위 조직·관련 기관·회차,
즐겨찾기의 조직 경로·연결 공고 수·공고별 분류를 Jetpack Compose에 반영했다.
제목 아래 요약은 상세에서 제공하고 카드에는 핵심 정보와 분류를 배치한다.
원문에 지정된 기관 역할과 조직 부모 관계는 구분하며, 기기에 저장된 조직을 임의로 변경하지 않는다.

Android Debug 빌드·Lint와 API 36.1 에뮬레이터 계측 테스트 3건을 통과했다.
기존 더블탭·세로 넘김·저장 유지·삭제에 더해, 채용 행사 상세의 기업/학교 분리와 대회 상세의 상위 조직·제2회 표시를 확인했다.

Android의 발견·즐겨찾기 전환을 상단 탭에서 하단 Material 3 NavigationBar로 변경했다.
iOS와 같은 두 항목의 순서와 아이콘·이름 구성을 사용하고, 시스템 하단 영역과 본문 간격은 Scaffold가 처리한다.
