# 태그 유형과 프로필 질문 — 제안 초안

2026-09-20. 사용자 요구는 태그 유형을 분리하고 프로필에서 지금 필요한 것을 발견하도록 돕는 것이다. 후속으로 사용자는 ‘나아갈 방향’과 ‘지금 필요한 경험’의 두 축 구분에 “좋아요”로 확인했다. 상황형 질문의 정확한 문구·매핑·배치·선택 규칙은 제안 단계다.

## 승인한 두 가지 축

| 유형 | 사용자 질문 | 예시 |
| --- | --- | --- |
| 방향 태그 | 어떤 방향으로 나아가고 싶나요? | 기획·디자인·백엔드·프론트엔드·창업 |
| 경험 태그 | 지금 어떤 경험이 필요하나요? | 팀협업·또래네트워킹·현직자교류·프로젝트완성·직무탐색·발표경험 |

창업은 직무와 같지 않으므로 화면의 상위 용어는 ‘직무’ 대신 ‘나아갈 방향’을 제안한다. 특정 직무를 준비하면서 창업에도 관심을 가질 수 있으므로 두 지향점을 배타적으로 보지 않는다. 선택 개수는 미정이다. 학과는 방향 추천의 단서로 사용하되 선택을 제한하지 않는다.

## 현재 상황에서 경험을 찾도록 돕기

- 혼자 해봐서 팀으로 만들어 보고 싶어요 → 팀협업 제안
- 관심 분야의 사람들을 만나고 싶어요 → 또래네트워킹 제안
- 현업 이야기를 듣고 피드백을 받고 싶어요 → 현직자교류 제안
- 시작한 것을 결과물로 완성해 보고 싶어요 → 프로젝트완성 제안
- 어떤 역할이 나에게 맞는지 알아보고 싶어요 → 직무탐색 제안
- 내 생각과 결과물을 설명해 보고 싶어요 → 발표경험 제안

상황 선택은 부족한 역량 진단이 아니라 선호 입력이다. 제안한 태그는 사용자가 확인·수정하고, 그중 가장 원하는 경험을 지정한다. 추정 태그를 확정된 사용자 요구처럼 숨겨 저장하지 않는다. 이 매핑과 문구는 미승인이다.

## 표시와 추천의 역할

프로필은 ‘나아갈 방향’과 ‘지금 원하는 경험’으로 나눠 제시한다. 프로그램 카드도 방향과 경험을 같은 해시태그 줄에 혼합하지 않고 구분해 보여주는 안을 제안한다. 예: 방향=백엔드·창업 / 경험=팀협업·프로젝트완성. 이는 가상 예시이며 실제 프로그램에 부여한 태그가 아니다.

현재 조건·자격은 별도 영역이며 원하는 방향이나 경험과 혼합하지 않는다. 자격 정보는 필요 시 입력하는 기존 승인 유지. 좋아요·추천 반응으로 추정한 선호와 명시 프로필 선택의 관계는 추가 합의가 필요하다.

방향에 창업을 포함할 때 기존 선택 직무 기준 모집 상태를 어떻게 확장할지, 프로필 수정 주기 등은 미정이다. 다중 선택 AND/OR는 아래 승인 절, 현재 회차 경험의 범위는 재기획 정본을 따른다. 기본 카드 탐색·모집 중 우선·C→B→A 정렬 계약을 임의로 변경하지 않는다.

## 검색과 추천의 조건 구분 — 최신 승인

사용자는 초기 ‘검색은 모두 일치(B), 추천은 일부 일치(A)’ 권고에 반례 검토를 요구했고, 수정안을 “좋아요”로 승인했다. 아래 규칙이 이전 일괄 AND 권고보다 우선한다.

| 조건 | 기본 동작 |
| --- | --- |
| 여러 방향 태그 | 하나라도 관련되면 포함(OR) |
| 여러 경험 태그 | 하나라도 일치하면 포함(OR), 두 경험 모두 일치하면 한 경험 일치보다 우선 |
| 방향과 경험 유형 사이 | 두 유형을 함께 충족(AND) |
| 반드시 함께 원하는 방향 | 사용자가 ‘모두 포함’을 선택 가능 |
| 추천 | 일부 일치도 후보에 포함하고 선호로 정렬 |

2026-09-21 경험 다중 OR와 두 경험 모두 일치 우선이 승인됐다. 후속 A 선택으로 모집 상태가 같을 때 최우선 경험 일치가 단순 일치 개수보다 우선한다고 확정했다. 최우선=현직자교류라면 현직자교류 1개 일치를 팀협업·발표경험 2개 일치보다 앞세운다. ‘모두 포함’ 조작 위치와 최우선 일치 여부가 같은 후보 사이의 행동 점수·일치 개수 관계는 아직 미정이다. 검색 결과 개수는 적용된 조건식으로 고유 프로그램 수를 계산한다. 0건일 때 부분 조합 제안도 이 조건식에 맞춰 구체화한다.

프로필 선호를 검색에 자동 강제하지 않기, 조건 변경 없이 부분 조합을 별도로 제시하기, 추천 행동으로 검색 포함 조건·개수를 바꾸지 않기는 앞선 모델 제안이다. 실제 UI·전환 규칙·경험 점수와의 연결은 추가 명세가 필요하다.

## 경험 적합도 순서 — 승인

모집 상태가 같을 때 최우선 경험과 다른 경험도 일치 → 최우선 경험만 일치 → 최우선은 없지만 다른 경험 일치 순서를 사용자가 “좋아요”로 승인했다. 행동 학습이 이 순서를 역전하는 정책은 승인되지 않았다.

## 경험 태그 부여 근거 — 승인

2026-09-21 사용자 B 선택으로 구체적인 활동 내용에 근거한 경험 태그 추론과 근거 제공을 허용한다. ‘직군별 팀으로 공동 결과물 제작’에서 팀협업을 도출하는 예시다. 단순 공동 참석에서 교류 기회를 단정하거나 참여 결과로 역량 향상을 보장하지 않는다. 추출 방법은 미정이며 불확실 후보와 검토 운영은 아래 후속 승인 절을 따른다.

### 태그별 적용 기준 초안

아래는 승인된 원칙의 적용 제안이며 실제 공고 분류 결과나 항목별 사용자 승인으로 간주하지 않는다.

| 태그 | 근거로 사용할 활동 내용 예시 | 단독으로는 부족한 근거 |
| --- | --- | --- |
| 팀협업 | 역할을 나눈 팀이 공동 과제를 수행 | 단순 단체 참가 |
| 또래네트워킹 | 참여자 간 소그룹 교류·상호 소개·지속 교류 모임 | 같은 장소 참석 |
| 현직자교류 | 현직자와 직접 질의응답·멘토링·피드백 | 현직자의 녹화 강의 시청 |
| 프로젝트완성 | 참여자가 결과물을 완성·제출·출시하는 과정 | 강의 수강만 명시 |
| 직무탐색 | 업무 역할·실무 과정 소개 또는 체험 | 모집 직군 이름만 명시 |
| 발표경험 | 참여자가 발표·피칭·데모를 진행 | 다른 사람의 발표 관람 |

태그 근거는 해당 모집 회차/활동 설명의 원문과 연결한다. 프로그램 전체의 과거 경험을 모든 새 회차에 자동 적용하지 않는다. 근거가 없다는 것과 해당 경험이 없다는 것을 구분한다. 사용자는 불확실한 후보 태그를 보류하고 본인이 나중에 처리하는 방향을 제안했다. 공개 노출과 관리자 검토의 구체 계약은 아래 승인 내용을 따른다.

## 사용자 직접 검토 운영 — 승인

사용자는 보류 태그를 나중에 본인이 처리하는 운영 방향을 제안하고 2026-09-21 “좋아요”로 다음 세부안을 승인했다.

- 공고와 근거 있는 태그는 노출하고 불확실한 후보 태그만 내부 검토 대기로 둔다. ‘보류’ 자체는 사용자 취향 태그가 아니다.
- 관리자 검토에서는 프로그램·해당 회차·후보 태그·보류 이유·원문 근거/링크를 함께 제공한다.
- 승인·다른 태그로 수정·후보 제외를 제공하고 근거가 부족하면 보류를 유지할 수 있게 한다.
- 후보 제외는 경험 부재 판정이 아니라 태그를 부여하지 않는 처리다.
- 미승인 후보 태그는 공개 검색 필터·추천 점수·프로그램 개수에 반영하지 않고 검토 승인 후 반영한다.

이 세부 운영안은 승인됐으며 관리자 UI·계정/권한·처리 기한·검토 후 규칙 학습 방식은 정하지 않았고 구현하지 않았다.

## 요구 경험과 제공 경험 구분

2026-09-22 사용자가 실제 검토 예시와 구분 설명에 “좋아요”로 확인했다. 공고에서 지원자에게 요구/우대하는 경험과 참여 활동으로 얻는 경험을 구분한다. 예시 데이터는 수동 검토 기록이며 운영 데이터 게시나 자동화 정확도 검증으로 보지 않는다.

남은 용어 확인: 또래네트워킹의 의미가 나이가 비슷한 사람인지, 같은 관심·목표를 가진 동료인지. 후자라면 동료네트워킹으로 명칭을 바꾸는 것은 모델 제안이다.

## 행위 기반 구조 재검토 — 진행 중

2026-09-22 사용자가 평면 경험 태그를 네트워킹/누구와:현직자 등 행위와 세부 조건으로 나누는 구조를 제안했다. [행위 기반 경험 초안](action-based-experience-tags-draft.md)을 검토 중이며 후속으로 상위 네트워킹 안에 현직자/동료 네트워킹이 포함되고 상위를 선택하면 하위도 검색되는 의미를 승인했다. 경험 표현은 이 포함 구조로 구체화한다. 다른 활동 유형의 목록·필드, 직무탐색과 실제 업무 체험의 구별, 최우선 경험과 일치 개수의 새 표현 대응은 미정이다.

최신 적용: 평면 6개 태그는 이전 제안 이력이다. 행위별 속성·경험 묶음·부분 일치·하위 검색 의미와 제작/과제수행 경계는 [행위 기반 문서](action-based-experience-tags-draft.md)의 2026-09-22 승인 절을 우선한다. 전체 어휘 사전과 점수 계산은 미정이다.
