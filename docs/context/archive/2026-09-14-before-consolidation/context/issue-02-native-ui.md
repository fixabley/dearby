## 목적

iOS·Android의 UI를 각 플랫폼의 기본 컴포넌트 중심으로 정비한다. 기능과 정보 구조는 일관되게 유지하면서 SwiftUI와 Jetpack Compose의 기본 표현·상호작용을 우선한다.

## 선행 작업

선행 이슈: #1

구조·상태 관리 리팩터링이 완료된 뒤 진행한다. 구조 변경과 외형 변경을 별도로 검토할 수 있도록 한다.

## 범위

- 탐색, 조직 즐겨찾기, 공고 상세 화면의 탭·내비게이션·버튼·목록·시트 등을 검토한다.
- iOS는 SwiftUI 기본 컴포넌트, Android는 Compose Material 3 컴포넌트를 우선한다.
- 기본 컴포넌트로 표현 가능한 커스텀 UI와 스타일을 정리한다.
- 카드 넘기기와 더블탭 저장 등 핵심 경험에 필요한 커스텀 표현은 유지할 수 있으며 이유를 기록한다.
- 두 플랫폼의 외형을 똑같이 강제하지 않는다. 기능과 책임을 맞추고 플랫폼별 관례를 따른다.
- 새 기능 추가와 API 변경은 범위에서 제외한다.

## 작업 및 완료 기준

- [ ] 화면별 기존 컴포넌트와 기본 컴포넌트 전환 후보, 유지할 커스텀 UI 및 이유를 정리한다.
- [ ] 두 앱에 네이티브 컴포넌트 우선 원칙을 적용하고 변경 전후 화면을 기록한다.
- [ ] 카드 탐색·저장·즐겨찾기·상세·삭제·저장 유지 흐름을 보존한다.
- [ ] 밝은/어두운 화면, 큰 글자, 스크린 리더의 주요 컨트롤 이름과 터치 영역을 확인한다.
- [ ] 두 앱의 빌드와 관련 검증 결과를 기록한다.

## 진행 방식

선행 작업의 플랫폼 worktree 정리 후, 최신 main에서 이슈 전용 iOS·Android worktree와 Orca 담당 세션을 구성한다. 플랫폼별 작업 기록과 검증 결과를 남기고 기능·컴포넌트 단위로 커밋과 PR을 나눈다.

## 2026-09-14 확정한 후속 방향

#1의 구현 PR #3·#4·#5·#6을 main에 통합했다. 이번 이슈의 디자인 구현은 아직 시작하지 않았다.

- iOS 참고: https://www.figma.com/ko-kr/community/file/1527721578857867021/ios-and-ipados-26
- 사용자의 목표는 App Store처럼 익숙한 네이티브 UI에 가깝게 구성하는 것이다. iOS 26+ SwiftUI 기본 컴포넌트와 시스템 표현을 우선하며 현재 도구 체인·지원 버전을 확인한다.
- 참고 Figma의 실제 내용은 아직 확인하지 못했다. 확인 가능한 원본 또는 Apple 디자인 자료와 현재 화면을 비교한 뒤 변경 후보를 정한다.
- Android는 Compose Material 3의 플랫폼 관례를 따르며 iOS 외형 복제를 강제하지 않는다.
- 탐색 카드 넘기기 → 더블탭 → 조직 즐겨찾기, 상세·지도·캘린더 흐름과 기존 상태·캐시 경계를 유지한다.
- iOS 실제 터치 swipe/doubletap 검증을 포함하고, 큰 글자·다크 모드·스크린 리더 등 기존 미검증 항목을 함께 확인한다.
