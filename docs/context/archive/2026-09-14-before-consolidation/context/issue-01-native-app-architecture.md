## 결과

iOS·Android의 컴포넌트·상태·저장 책임을 FSD 기반으로 분리하고 main에 통합했다. 기능별 커밋은 merge 방식으로 보존했다.

- 공통 설계: #3
- Android: #4
- iOS: #5
- 공고 데이터·지도·캘린더 공통 계약: #6

## 적용한 구조

- App 조립 → Pages → Widgets → Features → Entities → Shared 의존 방향.
- NoticeModel과 OrganizationModel은 독립 저장·조회. ViewModel이 두 모델을 조합해 화면별 State를 제공한다.
- Widgets/<Domain>/<Widget> 내부에는 View·ViewModel·State를 같은 폴더에 배치한다.
- 순수 UI는 표시값과 콜백을 받고, 공통 Primary/Secondary 버튼은 Shared/UI에 둔다.
- 즐겨찾기는 한 곳에서 소유하며 기존 조직 ID·UserDefaults/SharedPreferences 저장 호환성을 유지한다.
- 사용자 후속 요청으로 인메모리 → SwiftData/Room → 외부 source(현재 mock) 캐시, snapshot 무효화·실패 보존을 추가했다. 실제 API 연결은 제외한다.
- 장소·지도 및 기간별 캘린더 편집기 연결을 적용했다. 캘린더 메모는 검증된 공고 원본 URL만 사용한다.

## 검증 결과와 한계

플랫폼 최종 구현 단계에서 Android JVM 39건·계측 35건(실제 Room DB 5건 포함), debug/계측 APK 빌드, lint 오류 0건을 확인했다. iOS는 standalone 상태·조회·지도·캘린더·SwiftData 디스크 테스트와 simulator 빌드, 탐색/즐겨찾기/상세 및 재실행 smoke를 수행했다. 각 실행 시점과 상세 범위는 플랫폼 문서와 PR에 기록했다.

통합 시 두 앱의 파일 트리가 검증된 PR head와 동일함을 확인했다. 통합 main에서 공통 테스트 17건, 샘플 동기화, FSD iOS 66파일·Android 60파일 검사를 다시 통과했다. 플랫폼 전체 테스트를 이번 정리에서 재실행한 것은 아니다.

iOS 실제 touch swipe/doubletap, 물리 햅틱, 전체 접근성, 실제 캘린더 저장·동기화와 외부 지도 내부 화면은 미검증이다. iOS 카드 이동은 접근성 스크롤을 포함한 기존 회귀 확인 범위이며, 실제 터치 검증 완료로 주장하지 않는다. 전체 외형·접근성 점검과 실제 제스처 확인은 #2에서 이어간다.

## 승인 당시 Seed v2 (이력)

이후 사용자가 FSD, Model/ViewModel/State, SwiftData/Room 캐시 및 지도·캘린더 확장을 승인했다. 아래는 최초 승인 이력이며 현재 구현 원칙은 위 문서를 따른다.

```yaml
goal: iOS·Android의 컴포넌트·디렉터리·상태 관리 원칙을 문서화하고 현재 화면과 동작을 유지하면서 기존 코드를 리팩터링한다.
constraints:
  - iOS와 Android에 적용하며 API는 제외한다.
  - 기능 구분과 책임은 맞추고 상태 관리는 SwiftUI·Compose에 맞게 설계한다.
  - 화면·재사용 UI·상태·데이터 저장의 책임을 분리한다.
  - 플랫폼 기본 컴포넌트를 우선하며 실제 외형 변경은 후속 네이티브 UI 이슈에서 진행한다.
  - 재사용 UI는 표시 데이터와 이벤트 콜백으로 동작하며 저장소에 직접 접근하지 않는다.
  - 번들 데이터 공급을 향후 API 데이터로 교체할 경계를 두되 실제 네트워크 연결은 구현하지 않는다.
  - 즐겨찾기 상태는 한 곳에서 소유하고 저장·삭제 결과를 관련 화면에 일관되게 전달한다.
  - 새 외부 상태 관리·DI 라이브러리와 별도 빌드 모듈 분할 없이 기존 도구로 리팩터링한다.
acceptance_criteria:
  - 기능·책임별 디렉터리와 컴포넌트 분리가 두 앱에 적용된다.
  - 상태 소유·변경, 데이터 저장, 의존 방향과 새 기능 추가 기준이 문서화된다.
  - 카드 넘기기·더블탭 저장·즐겨찾기 목록·상세·삭제·재실행 후 저장 유지가 보존된다.
  - 두 앱의 빌드와 관련 테스트를 통과하고 회귀 검증 결과를 기록한다.
  - 기능별 디렉터리 트리와 파일 배치 예시를 문서로 제공한다.
  - 즐겨찾기 상태 로직을 앱 실행 없이 임시 저장소로 독립 테스트할 수 있다.
```
