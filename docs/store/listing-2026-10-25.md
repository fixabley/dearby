## 2026-10-26 쐐기 결정과 문안 방향

사용자 결정(2026-10-26): 앱의 쐐기는 **컨퍼런스 당일 도구(세션 시간표·세션 찜·이동 알림) + 명함 교환(어느 행사·어느 세션에서 만났는지 기록)** 이고, 발견·추천은 그 뒤의 재방문 이유다. 첫 실전은 10/28 우아콘 2026. 그래서 두 스토어 문안을 이 순서로 다시 썼다: 한 문장(`컨퍼런스 당일, 들을 세션과 만난 사람을 한곳에.`) → 시간표·찜·10분 전 알림 → QR 명함 교환·받은 명함의 행사·세션 표시 → 발견·맞춤 추천(`로그인 뒤`)·내 활동 진행 기록. 과장·보장 표현("놓치지 않아요" 류)은 쓰지 않고 앱에 있는 기능만 적는다.

- 앱 이름(`name.txt`·`title.txt`)은 `Dearby` 그대로다. 쐐기 문구는 iOS 부제·Play 짧은 설명이 담는다(App Store 2.3.7은 이름에 설명 문구를 넣는 것을 거절 사유로 본다). 이름을 `Dearby — 컨퍼런스 세션·명함`처럼 바꾸는 것은 제품 결정이라 하지 않았다.
- 제3자 행사 이름(우아콘 등)은 제목·부제·키워드·설명에 넣지 않는다(상표, 2.3.7). 테스터 모집 글([tester-recruitment-2026-10.md](../product/tester-recruitment-2026-10.md))에서만 쓴다.
- 받은 명함은 **활동(행사)과 그때 진행 중이던 일정 블록·세션**을 기록한다(계약 "명함 교환" › "교환 세션 맥락 — 2026-10-26": 서버가 저장 시각으로 자동 판정, 사용자는 고르지 않음; #432 서버, #434 iOS, #430 Android 병합). 문안은 `어느 행사·어느 세션에서 받았는지`로 적고, 자동 판정이라는 점을 설명에 한 문장 넣었다.
- 세션 이동 알림(native-v1.md "찜한 세션 이동 알림")은 `feat/session-reminder-ios`(#425)·`feat/session-reminder-android`(#428)가 2026-10-26 main에 병합됐다. 문안이 알림을 적으므로 그 뒤 빌드로 제출한다([release-cd.md](release-cd.md) "출시 문안의 전제").
- 사용자 결정(2026-10-26): 사용자에게 보이는 `찜한 세션`은 `내 시간표`로 쓴다(코드 식별자·API·analytics 이름은 그대로). 시간표 전환은 `전체 | 내 시간표`, 즐겨찾기 상단 행은 `내 시간표 · 세션 n개`. 문안의 "찜한 세션이 시작되기…"·"찜한 세션 시간표"는 명사구라 `내 시간표에 담긴 세션이 시작되기…`·`그 행사의 내 시간표`로 고쳐 썼다. 부제 `세션 찜`·짧은 설명 `찜`은 행위라 그대로다.
- Play 그래픽 이미지(`images/featureGraphic.png`, 원본 `shared/assets/brand/play-feature-graphic.html`)의 문구 `대외활동, 매일 맞춤으로`는 10-25 방향이라 이 결정과 어긋난다. **재제작 필요**(이 PR은 문서만 바꾸고 이미지는 손대지 않았다).

## Play 데이터 보안(Data safety) 답안

- 데이터 수집: 예. 제3자 공유: **아니요** — Firebase(Google)는 개발자 대신 처리하는 서비스 제공자로 Play 정의상 "공유"가 아니다([Firebase Play 공개 안내](https://firebase.google.com/docs/android/play-data-disclosure): 수집 데이터를 "subprocessors that assist us in providing Firebase services" 외에 넘기지 않음). 전송 중 암호화: 예(HTTPS, Firebase도 TLS). 삭제 요청: 앱 안 계정 삭제, 웹 https://dearby.wid.io.kr/support#delete-account.

## 심사 노트 초안 (두 스토어 공통)

- 로그인: 패스키·Apple·Google만 있고 비밀번호가 없습니다. 심사용으로 **[테스트 계정 — Apple 또는 Google 계정 권장(패스키는 심사 기기에 옮길 수 없음)]** 을 씁니다. Play "앱 액세스"에도 같은 안내를 넣습니다.
- 로그인 없이 쓸 수 있는 것: 발견(활동 둘러보기), 활동 상세, 세션 시간표 보기, 내 활동(이 기기에만 저장), 웹에서 받은 명함 보기. 로그인해야 하는 것: 세션 찜과 세션 이동 알림, 오늘의 맞춤 대기열과 추천 설정, 즐겨찾기·알림 목록·알림 수준, 지원 자격 정보, 프로필·명함 만들기·받은 명함. 비로그인에서 이 기능을 누르면 로그인 시트가 뜹니다.
- 세션 시간표: 트랙(강연장)이 나뉜 행사는 활동 상세 › `활동 일정`의 시간표 행을 누르면 모달이 열립니다(`전체 | 내 시간표`). 세션 카드의 하트가 찜이고, 찜한 세션은 내 활동 › 즐겨찾기(캘린더) 위 `내 시간표 · 세션 n개`에서도 봅니다. 시간표가 있는 활동이 심사 시점에 없으면 **[시간표가 있는 활동 이름]** 으로 안내합니다.
- 세션 이동 알림: 내 시간표에 담긴 세션 시작 10분 전에 **기기 로컬 알림**(서버 푸시가 아님)을 보냅니다. 권한은 첫 세션 하트 때 한 번 묻고, 설정 › 알림 › `세션 이동 알림`으로 끕니다. 심사 중에는 세션 시작 시각이 지나 알림이 오지 않을 수 있습니다.
- 맞춤 대기열: 로그인 뒤 발견 맨 위 `오늘의 맞춤 대기열` → 처음이면 추천 설정 질문(건너뛰기 가능) → 스토리형 카드. 매일 서버가 만듭니다.
- 지원 자격 정보: 프로필 › 추천 › `지원 자격 정보`에서 별도 동의 뒤 재학 상태·학년·태어난 해를 입력합니다(선택). 같은 화면에서 지울 수 있습니다.
- 푸시: 앱 시작 때 묻지 않고 **처음 프로그램 하트를 누를 때** 알림 권한을 묻습니다. 즐겨찾기마다 `전체`/`신청일만`/`없음`을 고르고, 해당 소식을 기기 시간대 오전 8시에 보냅니다. 심사 중 실제 푸시가 오지 않을 수 있으며 같은 소식은 발견 우상단 종의 알림 목록에도 쌓입니다.
- 캘린더: `겹치는 시간 확인`을 누를 때만 캘린더 권한을 묻고 기기 안에서만 비교합니다. `캘린더에 추가`는 시스템 일정 추가 화면을 열 뿐 앱이 직접 쓰지 않습니다.
- 명함 교환: 상대가 OS 카메라로 QR을 읽으면 웹 `https://dearby.wid.io.kr/cards/…`가 열리고, 앱이 있으면 유니버설 링크·`dearby://cards/…`로 앱에 저장합니다. 앱 안 카메라 스캔은 없습니다. 받은 명함에 붙는 행사·세션은 저장 시각으로 서버가 정하며 사용자가 고르지 않습니다. 받은 명함 상세 메뉴에 `신고하기`·`삭제하고 차단하기`, 설정에 `차단한 사람`이 있습니다.
- 계정 삭제: 설정 › 계정 › `계정 삭제`(App Store 5.1.1(v)).
- 사용 통계: Firebase Analytics(광고 식별자·IDFV·사용자 ID 없음, 추적 없음). 프로필 `사용 통계 보내기`로 끕니다.
