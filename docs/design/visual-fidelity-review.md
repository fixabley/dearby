# 컨펌 시안 대조 — 2026-09-27

추적: [#50](https://github.com/fixabley/dearby/issues/50). 기준: [화면별 최종 시안과 수정 우선순위](native-visual-contract.md).

## 변경 전 확인

이번 실행에서 담당자가 캡처한 실제 화면을 조율 세션에서 직접 열어 비교했다. 이전 실행 이미지를 새 검증 결과로 쓰지 않는다. iOS의 실패한 MCP 탭 뒤 `discovery.png`는 실제 상세 화면이었고, Android 최초 `current.png`는 런처였다. 둘 다 해당 앱 화면의 근거에서 제외하고 담당에게 수정하도록 전달했다.

| 흐름 | 관찰한 차이 | 수정 기준 |
| --- | --- | --- |
| iOS 상세 하단 | 기본 List 행마다 넓은 간격, 신청 버튼이 스크롤 내용에 묻힘, 상세에 탭바 노출, 민트 배경이 헤더까지 확장 | 섹션별 정보 위계, 고정 하단 저장·공식 사이트 버튼, 얇은 신청 기록 배너, 상세 탭바 숨김 |
| Android 내 프로필 | 텍스트 나열, 이름·직무와 연락처/이력의 간격·위계 불일치, 로그아웃/가져오기 동작이 프로필보다 먼저 보임 | 상단 프로필 요약, 연락처 행, 세로 이력, 편집 동작과 보조 계정 동작 분리 |
| Android QR | 독립 pill 모드 버튼, 일반 텍스트 제목, 일반 명함 타일, QR 외부 안내, 시안과 다른 CTA 모서리 | 확정 로고, 하나의 분할 컨트롤, QR 중심 카드, 카드 내부 안내, 명함 타일과 직사각형 CTA |
| Android 받은 명함 | 큰 입력 필드, 넓은 빈 공간, 카드에 연락처·이력이 기본 노출되지 않음, 이름·직무가 각각 별도 행 | 회색 검색창, 동일한 이름·직무 헤더, 민트 카드 묶음, 연락처와 연표, 하단 상세/나도 주기 |

Android 전 화면은 실제 Compose instrumentation test fixture 캡처다. before fixture가 1장인 상태는 카드 여러 장 중첩·넘김을 입증하지 않으므로 after에서는 여러 장·연락처·이력을 가진 데이터와 실제 앱 탭 포함 화면을 추가 확인한다. 아직 변경 후 일치·기능 회귀를 통과한 것으로 기록하지 않는다.

## 데이터 때문에 남는 차이

현재 catalog v1에는 콘텐츠 분류(컨퍼런스/연합동아리)와 검증된 이미지 URL이 없다. [#51](https://github.com/fixabley/dearby/issues/51)에서 계약·공식 출처 보완을 추적한다. 현재 UI는 실제 participationType에 따라 전체/참가등록형/선발형을 구분하고 사진 영역은 중립 자리표시자로 보존한다. 이 두 분류는 서로 동일한 의미가 아니며 시안 완전 일치로 기록하지 않는다. 샘플 컨퍼런스 사진을 실제 if(kakao) 사진인 것처럼 사용하지 않는다.

캘린더 충돌·푸시·외부 자동입력의 미구현 상태는 시각 수정으로 바뀌지 않는다. 큰 글자에서는 고정 높이·강제 축소 대신 내용이 늘어나거나 스크롤될 수 있어 기본 글자 시안과 배치가 달라질 수 있다.

## 중간 대조에서 돌려보낸 항목

- 실제 화면: iOS 기본 탭바 잔상/버튼 겹침, 낮은 보조 글자 대비, Android 빈 공간까지 늘어난 카드, 카드 안에 남은 상세 버튼, 중복 프로필 추가 버튼, QR 코드 비중 부족. 담당자가 같은 흐름을 다시 캡처하도록 했다.
- 카드 의미: 마지막 카드 뒤의 도달 불가능한 순환 카드, 같은 사람이 가진 여러 명함을 여러 상대라고 집계하는 표시, 내 명함 선택의 구성 이름표 누락. 상대 수와 카드 수를 구분하고 이름·직무는 고정한다.
- 동작 회귀: 전송 대기 중 다른 카드를 선택하는 혼란, 새 공유 명함 화면의 저장 확인 누락, Android 로그인 후 명함 보내기 복귀 누락, 활동 이력 전체 선택의 연락처까지 동시 변경, 정적 미리보기의 거짓 복사 완료 메시지. 시각 검사와 별개로 수정·검증한다.
- 접근성: 커스텀 분할 버튼 선택 상태, 연락처 공개/숨김 상태의 읽기 정보, 원본 QR 여백 유지, 큰 글자에서 카드 내부 내용과 버튼의 접근 가능성.

위 목록은 발견/교정 요청 기록이며 각 항목의 통과 증거는 최종 플랫폼 보고서와 대조한 뒤 기록한다. 초기 중간 캡처를 최종 결과로 표시하지 않는다.

## 통신 회귀 추가 조사

로그인 복귀 UI 검증 중 기존 로그아웃 요청이422로 거절되는 문제를 발견했다([#52](https://github.com/fixabley/dearby/issues/52)). 본문 없는 DELETE에 JSON/form Content-Type을 넣으면 Fastify 파서가 인증 핸들러 전에 거절하는 것을 격리 서버에서 재현했다. iOS는 무조건 붙이던 JSON 헤더를 본문이 있을 때만 보내도록 담당자가 수정하고, Android는 실제 전송 헤더를 조사한다. 각 플랫폼의 로그아웃 성공·서버 세션 폐기·로그인 복귀 증거 전까지 완료로 표시하지 않는다.

## 최종 구현 대조

조율 세션에서 양 플랫폼의 실제 캡처를 원본과 함께 열어 확인했다. 로고·흰 배경·연락처 행·연표·큰 QR·공유 메뉴·명함 타일·민트 카드 묶음·별도 상세/전송 행동을 반영했다. 일반 명함 헤더는 이름·직무를 유지하고 내 명함 선택에는 구성 이름표를 추가했다. iOS는 상세의 탭 영역을 제거했고 Android는 빈 공간까지 늘어나던 카드 높이를 줄였다. 긴 내용/큰 글자는 스크롤되며 QR 비중 때문에 아래 타일이 첫 화면 밖에 놓일 수 있다.

- [Android 비교 갤러리](../../apps/android/evidence/visual-fidelity/compare.html), [최종 검증·제한](../../apps/android/evidence/visual-fidelity/README.md). 원본, 변경 전 fixture, 변경 후 fixture/실제 MainActivity를 구분한다. 조율은 최종 QR/명함 선택/편집 화면과 실제 시스템 바 포함 캡처도 확인했다.
- [iOS 비교 갤러리](../../apps/ios/docs/evidence/visual-fidelity/comparison.html), [최종 검증·제한](../../apps/ios/docs/evidence/visual-fidelity/README.md). 실제 API 테스트 계정으로 렌더링했으며 스크롤 상단/하단 캡처는 별도다. 조율은 초기에 잘못 붙은 send-card-picker-top 이름이 실제 받은 명함 화면임을 발견해 증거 교정을 요청했다.
- 원본의 샘플 데이터, 생성된 기기 프레임/질감, OS 시스템 시트 모양까지 일치한다고 주장하지 않는다. 데이터 계약 차이 #51과 운영 연동은 위 한계를 유지한다. iOS 별도 작은 기기/VoiceOver 음성 탐색, Android 실기기/TalkBack은 이번 결과에 포함되지 않는다.

기능 회귀는 이미지 대조와 별도로 확인했다. 이력 전체선택의 연락처 공개 변경을 제거하고, 저장 전 안내/취소, 로그인 복귀, 서버 성공 후 상태 변경, 전송 중 선택 잠금, 고유 상대 집계를 교정했다. 양 플랫폼의 본문 없는 로그아웃을 교정했으며 iOS 실제204 후 폐기 토큰401, Android 실제 로그아웃/OTP 로그인/전송 선택 복귀가 통과했다. 조율 checkout 검사와 원격 CI 상태는 [검증 추적](../implementation/verification-matrix.md)에 기록한다.

Ponytail 검토에서는 실제 재사용 컴포넌트만 유지하고 기본 callback no-op, 중복 수신자 상태, 이동 후 사용하지 않는 import를 줄였다. 추가 추상 계층이나 의존성 도입은 없으며 정확성·저장·접근성 검토와 구분했다.

최종 상단 캡처에서 iOS 뒤쪽 카드 헤더가34pt 노출 간격 때문에 잘리고 반투명 배경으로 비치는 문제를 추가 확인했다. 후속02cd130에서 title3 기준56pt 가변 간격과 불투명 배경을 적용했고, 8b63646의 실제 명함 선택 상단 캡처를 조율에서 열어 모든 이름·직무·구성 이름표가 온전히 보이는 것을 확인했다. 잘못 매핑된 초기 top 캡처는 최종 증거에서 제거했다. 담당의 범위 한정 캡처/빌드/lint와 조율 최종 Debug build/strict lint도 통과했다.
