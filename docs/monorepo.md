# 모노레포 운영

## 구조와 변경 단위

Android 앱은 `apps/android/`, iOS 앱은 `apps/ios/`에서 관리합니다.
두 디렉터리는 같은 Git 저장소에 속한 일반 폴더입니다.
공통 API 명세와 예제 데이터는 `shared/contracts/`, 개발 문서는 `docs/`에 둡니다.

플랫폼별 빌드와 의존성은 각 앱에서 관리합니다.
API 변경에 두 앱이 영향을 받으면 명세와 클라이언트 변경을 하나의 PR로 검토합니다.
다른 플랫폼의 앱 소스를 직접 참조하지 않습니다.

## 작업 흐름

저장소 루트에서 작업 브랜치를 만들고 변경 파일을 선택해 커밋합니다.

```sh
git switch -c feature/my-change
git status
# 변경한 파일을 선택해 git add 후 커밋합니다.
git commit -m "Describe the change"
```

원격 저장소를 연결한 뒤에는 일반적인 `git push`와 `git pull --ff-only`를 사용합니다.
앱별로 별도의 커밋이나 참조 갱신을 할 필요가 없습니다.

## 빌드와 검증

빌드·실행 방법은 각 앱 README에 기록합니다.
플랫폼별 변경에는 해당 앱의 빌드와 관련 테스트를 실행합니다.
공통 명세 변경에는 두 플랫폼의 관련 검증을 실행합니다.
iOS CI는 macOS 실행 환경을 사용합니다.

공통 로직의 코드 공유는 필요에 따라 별도로 결정합니다.
Kotlin과 Swift 앱이 한 저장소에 있다고 해서 소스 코드가 자동으로 공유되지는 않습니다.

## 로컬 설정과 릴리스

iOS scheme은 공유하고 의존성 잠금 파일은 커밋합니다.
개발자별 SDK 경로, 빌드 결과, 환경 변수의 실제 값과 서명 키는 커밋하지 않습니다.
플랫폼별 버전과 배포 일정은 독립적으로 관리할 수 있습니다.
릴리스 태그를 사용한다면 `android/v1.0.0`, `ios/v1.0.0`처럼 구분합니다.
