# Android prototype structure

`app` owns Activity, navigation and two in-memory ViewModels. ActivityViewModel reads `GET /v1/activities` page by page with a debounced search and owns sample application reports; applied marks survive a new search. DemoViewModel owns the fictional profile, own cards and received-card exchange groups. `DemoFixtures.kt` is plain data, not a provider or repository.

`pages/activity`, `pages/profile`, `pages/cards` and `pages/wallet` render State and callbacks. They neither import each other nor call OS services. The reusable `widgets/card/cardContent` slice holds card display State, the mint card and stacked-card rendering. `shared/ui` holds theme (`TealFill` for filled teal surfaces), logo, buttons, DearbyTopBar (Material 3 `TopAppBar`) + TabActions, DearbySearchField, DearbyField/AddRow (stacked-label form rows), CenteredMessage (the single non-scroll layout; `DearbyEmptyState`/`DearbyErrorState` wrap it), ExampleBadge, InfoRow, PersonHeader, ContactSymbol and TimelineEntry; icons are `Icons.Rounded` only. Generic components accept strings and callbacks rather than domain models.

`features/application` handles an explicitly tapped safe external URL and local application demo. `features/calendar` compares fixed schedules and renders the timetable sheet. `entities/activity` parses `/v1/activities` and judges recruitment from the application window. No repositories, providers, network clients, persistence or empty replacement layers exist.

ViewModels survive Activity recreation but reset on process restart. Navigation, forms and sheets use Compose remember; rememberSaveable is not used. The one SavedStateHandle is AccountViewModel's Apple verifier and pending link token, which must outlive process death while Apple's page is open in a Custom Tab (2026-10-16). Card creation snapshots selected contacts/history. Editing changes the existing card ID without duplicating it. Received-card saves are idempotent; sample sending only marks the recipient reciprocal. Previous installed files are never opened or removed.

`scripts/check-fsd.py --self-test` checks package/path matching, downward dependencies, sibling-slice isolation, explicit exports and callback-only Page/Widget UI. Its 25 positive/negative cases cover the remaining slices, including shared card widgets; this lexical guard is not a compiler proof. Unit tests cover fixtures, filters, reset, interval boundaries, card snapshots/identity, deduplication, search and reciprocity. Instrumentation checks actual click flows and zero/nonzero overlap results; key card controls also run with Android font scale 1.3.

2026-10-24 맞춤 대기열(계약 "맞춤 대기열(스토리형 쇼츠)·조직 친화도·활동 벡터"): `pages/queue/DiscoveryQueuePage`는 M3·Compose `VerticalPager`로 활동 한 장마다 장면 셋(4초, 서버 `scenes`가 있으면 그 수만큼, 없으면 HOOK·HIGHLIGHTS(두 줄 이상)·DEADLINE을 앱이 만든다; 마지막 장면에서 멈춘다; 진행 막대는 애니메이션이 아니라 프레임 시각으로 세서 시스템 애니메이션 배율이 장면 길이를 바꾸지 않는다), 켄 번즈 커버(Coil, 없으면 로고 + 프로그램 id에서 뽑은 색조의 그라데이션), 오른쪽 버튼 줄·`⋯` `ModalBottomSheet`·`되돌리기` Snackbar·두 번 탭 하트·사용자 지정 동작, 끝 페이지 `더 받기`를 그린다. State와 콜백만 받는다. `app/QueueViewModel`이 `/v1/me/discovery-queue`(·`/refill`)와 `/v1/me/recommendation-signals`를 쓴다(로그인만; 2026-10-25부터 비로그인 대기열·기기 반응 저장은 없고 예전 키 `dearby.queue.signals`는 읽지도 지우지도 않는다). 대기열 항목은 활동 전체라 `entities/activity/api/parseQueue`가 읽는다(`AccountClient`는 원문 JSON만 돌려준다). 진입은 발견 맨 위 `widgets/recommendation/recommendationRows/QueueEntryRow` 한 줄이다(2026-10-25 사용자 결정으로 발견 `추천` 묶음·추천 행·퍼널 결과 미리보기는 지웠다). 퍼널을 마치지 않았으면 먼저 퍼널을 열고, 결과의 `맞춤 대기열 보러 가기`가 대기열을 연다. 진입 줄은 늘 보이고(비로그인이면 `로그인하면 나에게 맞는 활동을 골라 드려요`와 함께 로그인 시트를 연다), 조회가 실패하면(404 포함) 대기열 화면이 다시 시도 상태를 보인다. `app/QueueRoute`가 시스템 `애니메이션 삭제`(배율 0)를 동작 줄이기로, TalkBack을 자동 넘김 끄기로 넘기고 상태 표시줄 아이콘을 밝게 바꾼다. `자세히`는 발견에서 상세를 열고 닫히면 대기열로 돌아온다.
