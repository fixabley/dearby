# Dearby Android 클릭형 프로토타입

선택된 시안의 청록 액센트(중립색은 Material 3 시드 톤, 라이트·다크), 사진 카드, 상세 시간표, 신청 화면, 명함 화면을 Kotlin/Compose로 구현합니다. 서버 없이 고정 예시와 메모리 상태로 동작합니다.

- 활동 종류(2026-10-19 "활동 종류(category)"): `entities/activity/model/ActivityCategory`가 API 코드를 한글 이름으로 바꾼다(없으면 미분류). 발견에서 펼친 프로그램의 활동은 종류 소제목 아래 계약 순서로 묶이고(종류가 하나면 소제목 없음), 묶음 안은 모집 마감이 이른 순이며 모집 기간이 없는 활동은 활동 시작(`activitySchedule`의 `startAt`, 없으면 `startDate` 서울 0시)을 마감처럼 써 정렬하고 둘 다 없으면 맨 뒤다(2026-10-19), 상세에는 종류 칩 하나가 모집 상태 옆에 붙는다.
- 발견(2026-10-18 "발견 프로그램 묶음"): `GET /v1/discovery/programs`(`entities/activity/api/ActivityClient.kt`, 커서는 정수 오프셋)로 열린 활동이 있는 프로그램만 페이지 단위로 읽어 프로그램 카드(`widgets/activity/programCard/ProgramCard`, 아래 "발견 카드 리뉴얼") 목록으로 보인다. 카드 머리를 누르면 `GET /v1/activities?programId=&open=true`로 그 프로그램의 열린 활동을 읽어 카드 안에 활동 카드(`widgets/activity/activityCard/ActivityCard`)로 펼친다(최대 5페이지; 2026-10-19 "열린 활동 판정 일원화" 뒤 앱은 스스로 걸러내지 않는다). 검색창 아래 `마감 숨기기` 스위치(기본 켬, 메모리에만; 2026-10-19 "모집 중인 프로그램만 보기")를 끄면 `openOnly=false`로 최근 3년 안에 활동한 프로그램도 보이며, 그런 프로그램 카드의 보조 줄은 마감 대신 `최근 yyyy.M`을 쓴다. 펼친 프로그램의 다른 활동은 같은 `GET /v1/activities?programId=`에서 읽어 두 묶음으로 보인다(스위치가 꺼져 있으면 모집 중 활동 아래에 항상, 켜져 있으면 모집 중이 없을 때만 "지금 모집 중인 활동이 없어요" 아래에; 2026-10-19 저녁 결정): `모집 예정`(모집 시작 또는 모집 기간이 없으면 활동 시작이 아직 오지 않은 것, 가까운 순)과 `지난 활동`(최근 3년, 활동 시작 최근 순). 모집 중으로 이미 보인 활동은 두 묶음에서 뺀다. 종류 소제목은 없고 빈 묶음은 생략한다. 열린 활동이 1개인 프로그램과 검색어가 활동 이름에 맞은 프로그램은 스위치가 켜져 있을 때만 펼친 채로 시작하며 펼침 상태는 메모리에만 둔다. 검색창 입력은 300ms 쉰 뒤 `q`로 보내고 첫 페이지부터 다시 읽으며, 목록 끝에 가까워지면 `nextCursor`로 다음 프로그램 페이지를 붙인다. 모집 상태 라벨은 `application` 기간만으로 정하며 시각 일정은 시각, 날짜 일정은 서울 날짜(`startDate ≤ 오늘 < endDateExclusive`)로 비교한다(모집 기간이 없을 때만 `확인 필요`). 상세 CTA는 모집 상태가 마감(모집 마감이 지났거나 활동이 끝남)이 아니면 https `applicationUrl`(없으면 `officialUrl`)을 외부 브라우저로 열고 라벨은 `신청 사이트 열기`(applicationUrl 있음)·`공식 사이트에서 신청`(officialUrl만)이며, 돌아오면 "신청하셨나요?"를 묻는다(open·upcoming·모집 정보 없음 모두; 2026-10-19 밤 "신청 확인 조건 완화·공개 applicationUrl", `ActivityModel.isClosed`); 마감이면 `공식 안내 보기`로 열고 묻지 않는다(2026-10-19 카드 리뉴얼로 카드의 신청 버튼은 없다). `imageUrl`은 내 활동 행에서만 Coil로 보이고 없으면 일정 타일을 그린다(활동 상세의 이미지 머리는 2026-10-19 밤 "활동 상세 이미지 섹션 제거"로 없앴다; 모델의 `imageUrl`은 남는다). 실패하면 오류와 다시 시도, 프로그램이 없으면 "지금 모집 중인 프로그램이 없어요"이며 예시를 섞지 않는다. 유형 칩(참가등록·선발)은 Android 발견 화면에 없어 `participationType`을 보내지 않는다. 다른 검색어를 넣어도 내 활동의 신청 표시는 남는다. `INTERNET` 권한은 실제 연결 범위에 한해 쓰고, http는 debug의 10.0.2.2·localhost·127.0.0.1만 허용한다(`src/debug` network security config). 2026-10-19 밤 정정("마감 숨기기"): 스위치를 켜도 마감된 활동만 숨긴다 — 서버는 모집 중이거나 모집 예정인 프로그램을 돌려주고(`upcomingActivityCount`·`nearestRecruitmentStartAt`), 카드 배지는 모집 중 + 모집 예정 수이고 보조 줄은 모집 중이 없으면 `M월 d일 시작`, 펼치면 `모집 예정` 묶음은 항상, `지난 활동`(최근 3년)은 스위치를 껐을 때만 보인다. 세 묶음이 모두 비면 "지금 모집 중인 활동이 없어요"만 남긴다.
- 태그(2026-10-19 "태그(얻을 수 있는 것)"·같은 날 밤 "태그 칩 줄 제거"): `entities/activity/model/Tag`. 태그는 **검색 조건**으로만 쓴다(검색어 `q`가 태그 이름에 맞으면 서버가 찾아 준다). 검색창 아래 사전 칩 줄과 `GET /v1/tags`·`tagIds`는 앱에서 없앴다(API에는 남는다). 프로그램 카드는 태그 칩 최대 3개 + `+n`, 활동 카드에는 없고(2026-10-19 카드 리뉴얼), 활동 상세는 종류 칩 아래 전체를 보인다. 응답에 `tags`가 없으면 빈 목록이다.
- 발견 카드 리뉴얼(2026-10-19 "발견 카드 리뉴얼", One UI 알림 카드 느낌): 프로그램 카드(`ProgramCard`)는 Material 3 `OutlinedCard`(모서리 20·1dp 선·그림자 없음)로, 왼쪽 44dp 로고 자리(`ProgramSummary.logoUrl`, 2026-10-19 밤 "프로그램 로고": API origin 기준 `/v1/programs/{id}/logo?v=`를 `fetchPrograms`가 절대 URL로 만든다)에 Coil `AsyncImage`(Crop, 모서리 14)를 보이고 로딩 중·실패·null이면 프로그램 이름 첫 글자 아바타(`onState`로 성공 전까지만 아바타를 그려 투명 로고 뒤에 민트 타일이 비치지 않는다), 가운데 이름(굵게) → 조직 → 분야 1개(민트)+성격 아이콘+글자 칩 한 줄(`TagChipRow`, 넘치면 `+n`, 줄바꿈 없음, 접근성에서는 머리 라벨에 묶임) → 검색이 활동 이름에 맞으면 그 아래 `맞는 활동 n개`(2026-10-24 "태그 아이콘+라벨·분야 1개·자동 펼침 없음"), 오른쪽 위 `Badge`(32dp, 모집 중 + 모집 예정 수, 0이면 회색) 아래 `M월 d일 마감`/`M월 d일 시작`/`최근 yyyy.M` 한 줄이다. 목록은 프로그램을 저절로 펼치지 않고 머리를 누를 때만 펼쳐지며 배지 자리가 `IconButton`(`Icons.Rounded.ExpandMore` 회전, 44dp, 접근성 `접기`)으로 바뀐다. 높이는 `animateContentSize(spring(dampingRatio 0.8, stiffness MediumLow))`, 내용은 `expandVertically + fadeIn`/`shrinkVertically + fadeOut`(페이드는 `tween(220, FastOutSlowInEasing)`), 화살표는 180° 회전이며 애니메이터 배율 0(동작 줄이기)에서는 `snap`으로 즉시 바뀐다. 접근성에서 머리는 `펼침`/`접힘` 상태를 가진 버튼이고 머리만 누를 수 있어 활동 카드는 각자 읽힌다. 활동 카드(`ActivityCard`, Material 3 `Card`)는 로고 없이 왼쪽 위 활동명, 오른쪽 위 모집 상태 `SuggestionChip`(접근성에서는 카드의 상태 설명; `모집 중` 청록 채움 / `모집 예정` 민트 / `마감` 회색; `application`이 없어 판정할 수 없으면 회색 `확인 필요`), 아래 `모집`(모집 기간 문구, 없으면 `미정`; 날짜 일정 모집은 `M월 d일 – M월 d일`로 끝 날짜 하루 전까지)·`활동`(활동 기간 문구, 없으면 `미정`)·`장소`(장소 이름, 없으면 줄 생략) 세 줄이다. 모집이 지나지 않았으면(모집 중·모집 예정) `모집` 값은 청록 굵은 글씨에 줄 전체 민트 바탕(모서리 8)이다. 펼친 안의 순서는 종류 묶음(모집 중) → `모집 예정` → `지난 활동`이며 소제목은 작은 보조 글자다. 색·글꼴은 기존 토큰만 쓴다(`마감` 칩은 `Line` 바탕·`Quiet` 글자). 2026-10-19 사용자 규칙으로 같은 역할의 Material 3 컴포넌트를 우선 쓴다.

- 겹치는 시간(2026-10-19, 계약 "기기 캘린더 겹침"; 2026-10-22 "겹침 확인 시간"): 비교 구간은 활동 기간(`activitySchedule`)과 세부 일정(`schedules`)에서 만든다(모집 기간은 넣지 않는다, `StageSchedule.windows`) — 시작·끝 시각이 다 있는 일정은 그 시각, 날짜만 있는 일정은 어드민이 정한 `overlapCheck {startTime, endTime}`(서울 HH:mm)을 `[startDate, endDateExclusive)`의 날마다, 둘 다 없으면 비교하지 않는다. 하나라도 있으면 활동 상세에 `겹치는 시간 확인하기`(`ActivityState.overlapCheckable`), 없으면 그 자리에 "이 활동은 시간이 정해진 일정이 없어 겹침을 확인할 수 없어요" 한 줄; 진행 단계의 `hasWindow`도 같은 규칙이다. 시각은 `instant()`(`OffsetDateTime`)로 읽는다(`+09:00` 오프셋을 `Instant.parse`로 읽지 않는다). `겹치는 시간 확인`을 누를 때만 `READ_CALENDAR`를 요청하고(`features/calendar/CalendarConflictFlow`), 허용되면 활동 일정이 걸친 구간의 기기 일정을 `CalendarContract.Instances`로 읽어(`DeviceCalendarSource`, 종일 일정 제외) 기기 안에서 겹침을 계산합니다. 제목·시각은 화면에만 쓰고 저장·전송하지 않으며 화면을 닫으면 버립니다. 거부하면 이유와 `설정 열기`를 보이고 신청은 막지 않습니다. 이전의 고정 바쁜 시간 예시는 지웠습니다.

예시 모집 상태는 날짜가 지나도 바뀌지 않습니다. 모든 편집·저장·신청·교환 상태는 프로세스 종료 후 초기화됩니다. 실제 접수·선정·계정 생성·전송 완료를 주장하지 않습니다.

## 연결 설정

계약 `shared/contracts/native-v1.md`의 "연결 설정"을 따른다. 코드에는 운영 도메인을 두지 않는다.

- 환경값 `DEARBY_API_ORIGIN`(없으면 같은 이름의 Gradle 속성 `-P`)이 `BuildConfig.API_ORIGIN`으로 들어간다. `DEARBY_WEB_ORIGIN`(기본 `https://dearby.wid.io.kr`)은 `BuildConfig.WEB_ORIGIN`(명함 QR·캘린더 메모·활동 공유 링크·개인정보 처리방침)과 manifest placeholder `webHost`(App Links 호스트)로 들어간다.
- 맞춤 대기열 끝 광고(2026-10-25, `features/ads/QueueAd`): `ADMOB_ANDROID_APP_ID`(manifest placeholder `adMobAppId` → `com.google.android.gms.ads.APPLICATION_ID`)와 `ADMOB_ANDROID_QUEUE_NATIVE_UNIT_ID`(`BuildConfig.ADMOB_NATIVE_UNIT_ID`)는 같은 방식(환경 변수·Gradle 속성)이다. Debug는 항상 Google 테스트 앱 ID·네이티브 테스트 단위 ID를 쓰고, Release는 둘 다 있어야 광고를 요청한다(없으면 manifest에 테스트 앱 ID만 넣어 시작 크래시를 막고 MobileAds 초기화·요청 없이 광고 장면을 건너뛴다). 대기열 응답을 받은 뒤 1개를 미리 요청하고, 받으면 마지막 활동 다음·끝 화면 앞에 광고 장면 한 장을 넣는다. 마지막 활동에서 넘길 때까지 못 받았으면(요청 중·실패) 그 열람에서는 생략하고 다시 요청하지 않으며, `더 받기` 뒤에도 넣지 않는다. 광고 장면은 자동 넘김·탭·버튼 줄·추천 신호 없이 상하 스와이프와 닫기만 있다. 요청은 비개인화(`npa=1`)·최대 등급 PG·게시자 자사 ID 끔(`MobileAds.putPublisherFirstPartyIdEnabled(false)`)이며 AdMob이 광고 ID(`AD_ID` 권한)를 쓴다. Privacy Sandbox 권한(`ACCESS_ADSERVICES_AD_ID`·`ATTRIBUTION`·`TOPICS`)은 manifest에서 뺀다.
- release: 빌드가 실제로 돌 때(`preReleaseBuild`)만 값이 `https://<도메인>`(IP·포트·경로·대문자 없음)인지 검사하고, 아니면 실패한다. debug 빌드·단위 테스트·Studio sync에는 영향이 없다.
- debug: 값이 없으면 에뮬레이터 호스트의 `http://10.0.2.2:3000`을 쓴다.
- App Links(2026-10-22 계약 "유니버설 링크·App Links·활동 공유·오픈그래프"; 2026-10-18 "만들지 않는다"를 대체): `MainActivity`의 `android:autoVerify="true"` https 필터가 웹 origin 호스트의 `/cards/`·`/activities/`만 받는다(검증 파일은 웹의 `/.well-known/assetlinks.json`; Play 앱 서명 키 지문은 첫 AAB 업로드 뒤 추가 예정이라 그 전 Play 설치본은 브라우저로 연다). `shared/config/AppLinks.kt`의 `cardLink(link, webOrigin)` 하나가 `dearby://cards/<id>`와 `https://<웹 origin>/cards/<id>`를 함께 해석한다(`CardLink.web`이 입구).
  - `dearby://cards/…`(웹 `Dearby 앱에 저장`): 지금처럼 바로 저장하고 받은 명함 상세를 연다.
  - `/cards/<id>?activity=&code=`: 로그인했고 받은 명함에 이미 있으면 명함 탭 › 받은 명함 › 그 상세(저장 요청 없음). 아니면 공유받은 명함 보기(`pages/wallet/SharedCardPage`, `GET /v1/cards/:id?code=`, 받은 명함 상세와 같은 `CardContent`, 활동이 있으면 `<프로그램> <활동>에서 받은 명함`, `신고하기`, 주 버튼 `받은 명함에 저장` = 기존 저장 흐름). 내 명함이면 버튼 대신 `내 명함이에요.`, 조회 실패는 저장 안내와 같은 문구를 화면 안에 보인다. 로그아웃 상태의 신고는 `로그인한 뒤 신고할 수 있어요.` 안내만 한다.
  - `/activities/<id>`(숫자, 쿼리는 무시): 발견 탭으로 가서 그 활동 상세를 연다. 발견이 불러오지 않은 활동은 `GET /v1/activities/:id`로 먼저 읽고, 없으면 `더 이상 볼 수 없는 활동이에요.`, 읽지 못하면 다시 시도 안내를 띄운다(상세에 따로 "없는 활동" 화면이 없어서 안내 창으로 대신했다).
  - 활동 상세 상단 공유(`활동 공유`)는 `<웹 origin>/activities/<id>`(캘린더 메모와 같은 주소)를 `ACTION_SEND` text/plain chooser로 보낸다(`EXTRA_SUBJECT`·`EXTRA_TITLE` = 활동 이름). 공식 안내 링크를 보이던 창은 없앴다.

## 출시 빌드와 Play 업로드 키 (2026-10-19)

- 업로드 키는 저장소 밖 `~/.dearby-deploy/android-upload.jks`(PKCS12, RSA 4096, alias `upload`)이고, 경로·비밀번호·alias는 `~/.dearby-deploy/android-signing.env`에만 있다(`ANDROID_KEYSTORE_PATH`·`ANDROID_KEYSTORE_PASSWORD`·`ANDROID_KEY_ALIAS`·`ANDROID_KEY_PASSWORD`, 권한 600). 같은 이름의 Gradle 속성으로도 줄 수 있다. 네 값이 모두 있을 때만 release가 이 키로 서명되고, 없으면(CI·lint) 서명 없는 release다.
- 빌드: `set -a; . ~/.dearby-deploy/android-signing.env; . ~/.dearby-deploy/mobile.env; set +a; DEARBY_API_ORIGIN=https://api.dearby.wid.io.kr DEARBY_WEB_ORIGIN=https://dearby.wid.io.kr ./gradlew bundleRelease` → `app/build/outputs/bundle/release/app-release.aab`. 확인은 `jarsigner -verify` 또는 `apksigner verify --print-certs`.
- Play Console은 Play 앱 서명을 쓴다: 이 키는 **업로드 키**이고 사용자에게 배포되는 APK는 Google이 보관하는 앱 서명 키로 다시 서명한다. 첫 AAB를 올릴 때 Play 앱 서명에 등록하면 업로드 키 인증서가 고정되며, 잃어버리면 콘솔에서 업로드 키 재설정을 요청해야 한다. OAuth·App Links에는 Play 콘솔 "앱 서명" 화면의 **앱 서명 키** SHA-1·SHA-256을 쓴다(업로드 키 지문이 아니다).
- `versionCode`는 올릴 때마다 1씩 올린다(같은 값은 거부). `versionName`은 `0.1.0`. 축소(`isMinifyEnabled`)는 켜지 않았다.

## 패스키 로그인 (2026-10-10)

계약 [native-v1 "패스키 로그인"](../../shared/contracts/native-v1.md)을 따른다. 이메일 인증번호 로그인은 없앴다.

- 흐름: 로그인 시트 `pages/account/SignInSheet.kt`의 "패스키로 로그인"(기본; 2026-10-25부터 패스키 가입 "새 패스키로 시작"은 없고 새 계정은 Apple·Google로 만든다) → `app/AccountViewModel` → `entities/account/api/AccountClient`의 `/v1/auth/passkeys/*` 옵션 요청 → `features/passkey/Passkeys`(Credential Manager)에 `options` JSON을 그대로 넘김 → 결과 JSON을 `credential`로 완료 요청 → TokenPair.
- 저장: Keystore AES-GCM `SessionVault` 새 이름 `account.tokens.v3`에 access·refresh token만 둔다(서버 응답도 토큰 두 개뿐이다). 사용자 id·만료는 access token 클레임에 있고, 401을 받으면 갱신한다. 이전 저장(`session`, 이메일 로그인의 `account.session.v2`)은 읽거나 지우지 않는다.
- 401: `/v1/auth/refresh`를 한 번 시도하고(동시에 401을 받아도 갱신은 한 번), 거절되면 토큰을 지우고 로그인 시트로 돌아간다. 네트워크 오류면 토큰을 남긴다. 로그아웃(`AccountViewModel.signOut`)은 `/v1/auth/logout` 뒤 네트워크 실패여도 기기 토큰을 지운다. 로그아웃 버튼은 2026-10-20부터 설정 화면의 계정 섹션에 있다(위 "설정").
- 계정 삭제(2026-10-16, 계약 "계정 삭제"; 2026-10-20부터 설정 화면의 계정 섹션에만 있고 내 프로필의 빨간 버튼은 지웠다): 확인 창("계정을 삭제할까요?" / 삭제·취소) → `ProfileViewModel.deleteAccount` → `AccountViewModel.deleteAccount`(`authorized`로 `DELETE /v1/me`, 401이면 갱신 후 재시도) → 204면 `SessionVault`를 지우고 로그인하지 않은 상태로 돌아가 "계정을 삭제했어요. 기기에 남은 패스키는 비밀번호 관리자에서 지울 수 있어요."를 한 번 띄운다. 갱신이 거절되면 이미 로그아웃된 것으로 보고 만료 안내, 그 밖의 실패는 "계정을 삭제하지 못했어요. 잠시 후 다시 시도해 주세요."와 함께 토큰을 남긴다. 요청 중에는 버튼을 막는다. 기기에 저장한 계정 데이터는 토큰뿐이고, 로그아웃 상태가 되면 QR 탭의 명함·공유 링크와 프로필 캐시(메모리)도 비운다.
- 사용자가 패스키 창을 닫으면 오류 없이 시트로 돌아간다. 기기에 패스키가 없으면 Apple·Google로 시작하라고 안내한다. 패스키는 Android 9(API 28) 이상에서만 쓸 수 있다(minSdk 26).

계약 [native-v1 "애플 로그인"](../../shared/contracts/native-v1.md)의 웹 방식을 따른다. 패스키와 함께 고를 수 있다.

- 버튼: 로그인 시트(`SignInSheet`, 화면마다 `app/SignInRoute`로 연다. 맨 위에 심볼 + 앱 이름 `DearbyBrand`, 2026-10-19 사용자 결정: 일반 화면 상단 바의 로고는 뺐다)와 첫 실행 소개에 검은 "Apple로 계속하기"(`shared/ui/AppleSignInButton`). 저장소에 애플 로고 자산이 없어 글자만 둔다.
- 시작: `features/oauth/OAuthVerifier`가 32바이트 무작위 verifier(base64url, 43자)와 SHA-256 해시를 만든다 → `/v1/auth/apple/web/start` → 받은 https `authorizeUrl`을 Custom Tab(`androidx.browser`)으로 연다. 탭을 연 뒤에는 기다리지 않으므로 사용자가 탭을 닫아도 시트가 멈추지 않는다. 503이면 "지금은 애플 로그인을 쓸 수 없어요."
- verifier 보존: `AccountViewModel`의 `SavedStateHandle`에 둔다(로그에 남기지 않는다). 회전·프로세스 종료 뒤 복원에도 남고, 결과 링크를 받으면 무엇이 오든 지운다(한 번만 쓴다).
- 돌아오기: `MainActivity`(`launchMode="singleTask"`)의 `dearby://auth/apple` intent filter. 같은 인스턴스가 `onNewIntent`로 받고 위의 Custom Tab이 닫힌다. `shared/config/AppLinks.authRedirect`는 `?code=<UUID>` 하나 또는 `?error=cancelled|failed`만 받고 나머지는 버린다. 재생성된 Activity가 같은 시작 intent를 다시 받으면 처리하지 않는다.
- 자동 연결(2026-10-17 사용자 결정): 202 직후 `PendingAccountRoute`가 먼저 `AccountViewModel.autoLinkPending`을 한 번 실행한다. `Passkeys.get`은 `setPreferImmediatelyAvailableCredentials(true)`라 이 기기(비밀번호 관리자)의 Dearby 패스키만 묻는다. 있으면 생체 인증 한 번으로 로그인·연결, `NoCredentialException`이면 묻지 않고 바로 `/v1/auth/apple/register`로 새 계정을 만든다. 사용자가 패스키 프롬프트를 닫으면(null) 그때만 아래 선택 화면을 띄운다(`AccountState.pending.auto`).
- 교환: `/v1/auth/apple/web/exchange` 200은 패스키와 같은 TokenPair로 `SessionVault`에 저장한다. 202는 `MainActivity`가 모든 화면 위에 `LinkAccountSheet`("새 계정으로 시작" → `/v1/auth/apple/register`, "기존 패스키 계정에 연결" → 패스키 로그인 뒤 그 토큰으로 `/v1/me/identities/apple`)를 띄운다. linkToken도 `SavedStateHandle`에 두고 선택·닫기에서 지운다. 연결이 실패하면 iOS와 같이 패스키 토큰을 저장하지 않고 `/v1/auth/logout`을 시도한 뒤 로그인하지 않은 상태로 안내한다: 401 "애플 로그인 시간이 지났어요. 애플로 다시 시작해 주세요."·400 "이미 다른 계정과 연결돼 있어서 연결하지 못했어요."(둘 다 선택 화면을 닫는다, 400은 `AccountError.BAD_REQUEST`), 503·네트워크 "지금은 애플 로그인을 쓸 수 없어요."(선택 화면 유지). 401·`error=failed`는 다시 시도 안내, `error=cancelled`는 안내 없음.
- 실제 로그인은 서버의 Services ID·Return URL(`APPLE_CLIENT_IDS`)이 있어야 확인할 수 있다.

## 구글 로그인 (2026-10-19 네이티브)

계약 [native-v1 "구글 로그인 — 2026-10-19 네이티브 SDK로 전환"](../../shared/contracts/native-v1.md)을 따른다. 2026-10-18의 Custom Tab 웹 방식(`/web/start` → `dearby://auth/google` → `/web/exchange`)은 지웠다.

- 흐름: `AccountViewModel.signInWithGoogle` → `POST /v1/auth/google/nonce` → `features/google/GoogleSignIn`(Credential Manager + `com.google.android.libraries.identity.googleid`, `GetGoogleIdOption(serverClientId, nonce, filterByAuthorizedAccounts=false)`) → `GoogleIdTokenCredential.idToken` → `POST /v1/auth/google {idToken, nonce}`. 200은 패스키와 같은 TokenPair, 202(처음 보는 Google 계정)는 애플과 같은 `PendingAccountRoute`·`LinkAccountSheet`(`/v1/auth/google/register`, `/v1/me/identities/google`)다. 계정 선택 창을 닫으면 안내 없이 돌아가고, 기기에 Google 계정이 없으면(`NoCredentialException`) 계정 추가를 안내한다.
- 빌드 설정 `GOOGLE_SERVER_CLIENT_ID`(환경 변수 또는 같은 이름의 Gradle 속성 → `BuildConfig.GOOGLE_SERVER_CLIENT_ID`): Google Cloud의 **웹 애플리케이션** OAuth 클라이언트 id다(ID 토큰의 `aud`; 서버 `GOOGLE_CLIENT_IDS`에도 같은 값). Android OAuth 클라이언트(패키지 `io.wid.dearby` + 서명 SHA-1)는 콘솔에만 등록하고 앱에는 값이 없다. 값은 저장소·채팅에 두지 않고 로컬 `~/.dearby-deploy/mobile.env`에서 기기 설치 빌드에 넘긴다. 비어 있으면(CI 포함) `AccountState.googleAvailable`이 false라 버튼이 없다. 서버가 nonce에 503을 돌려주면 그때도 숨긴다.
- 버튼: 로그인 시트와 첫 실행 소개의 애플 버튼 아래 "Google로 계속하기"(`shared/ui/DearbyGoogleButton`, `surface` 바탕·`surfaceContainerHighest` 테두리). 공식 "G" 로고 자산이 아직 없어 굵은 G 글자로 대신한다.
- 실제 로그인은 콘솔의 Android 클라이언트에 빌드 서명의 SHA-1이 등록돼 있고 서버 `GOOGLE_CLIENT_IDS`가 있어야 확인할 수 있다.

### 도메인 연결 (`wid.io.kr`)

패스키는 RP ID `wid.io.kr`이 이 앱을 신뢰해야 동작한다. 아래 두 값을 서명 인증서마다(디버그, 배포) 넣는다. Play 앱 서명을 쓰면 배포 값은 업로드 키가 아니라 Play Console의 "앱 서명 키 인증서" SHA-256이다.

1. `https://wid.io.kr/.well-known/assetlinks.json`(운영 ingress가 낸다):

   ```json
   [{
     "relation": ["delegate_permission/common.get_login_creds"],
     "target": { "namespace": "android_app", "package_name": "io.wid.dearby",
       "sha256_cert_fingerprints": ["<서명 SHA-256, AA:BB:… 형식>"] }
   }]
   ```

2. API `WEBAUTHN_ALLOWED_ORIGINS`에 `android:apk-key-hash:<같은 SHA-256의 base64url, 패딩 없음>`.

`sha256_cert_fingerprints`는 배열이라 디버그·배포 지문을 한 항목에 함께 넣을 수 있다. 두 값을 구하는 명령(디버그 키스토어 예시, 배포는 키스토어·alias·비밀번호를 바꾼다):

```sh
KEYTOOL="$JAVA_HOME/bin/keytool"
# assetlinks용 hex. 한국어 로캘에서 keytool -v가 실패하면 -J-Duser.language=en을 붙인다.
"$KEYTOOL" -J-Duser.language=en -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android | grep SHA256:
# 허용 origin용 base64url
"$KEYTOOL" -exportcert -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android \
  | openssl sha256 -binary | openssl base64 | tr '+/' '-_' | tr -d '='
```

디버그 키스토어는 개발 기기마다 다르므로 각자 값을 넣는다. Play Console 값(hex)만 있으면 `echo <hex 콜론 제거> | xxd -r -p | openssl base64 | tr '+/' '-_' | tr -d '='`로 바꾼다. 로컬 API로 확인하려면 `DEARBY_API_ORIGIN`을 지정한다(Debug 기본 `http://10.0.2.2:3000`은 Kotlin API 포트와 다르다). 그래도 RP ID가 `wid.io.kr`이므로 assetlinks가 배포되기 전에는 패스키 창이 실패한다.

```sh
export JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home'
export ANDROID_HOME=/Users/jominjun/Library/Android/sdk
./gradlew :app:assembleDebug :app:lintDebug
python3 scripts/check-fsd.py --self-test
```

실제 실행 결과는 `docs/VERIFICATION.md`, 구조는 `ARCHITECTURE.md`를 참고하세요.

## 즐겨찾기·새 모집 푸시 (2026-10-25)

계약 [native-v1 "즐겨찾기(하트)·새 모집 푸시 알림"](../../shared/contracts/native-v1.md)을 따른다.

- 하트: 활동 상세 머리·펼친 활동 행·맞춤 대기열 오른쪽 줄(활동은 하트 옆 `+` 내 활동에 추가, 상세 우상단 `추가`는 없앴다)과 프로그램 카드. 즐겨찾기하면 종 버튼이 생기고 시트에서 `전체`·`신청일만`·`없음`을 고른다. 비로그인 하트는 로그인 시트. 발견 API는 비로그인 요청이라 `favorited`를 받지 않으므로 로그인하면 `GET /v1/me/favorites`의 id 집합으로 하트를 그린다(`app/FavoritesViewModel`). 쓰기 실패(서버 배포 전 404 포함)는 하트를 되돌리고 스낵바를 띄운다.
- 내 활동 탭 위 `PrimaryTabRow` `내 활동 | 즐겨찾기`. 즐겨찾기는 캘린더 하나(2026-10-26 `목록 | 캘린더`·목록·밀어서 해제를 없앴다; 예전에 `dearby.favorites`에 저장한 보기 값은 읽지 않는다; 앱 안 보기만, 기기 캘린더에 쓰지 않음) 아래 `날짜 없는 즐겨찾기`에 프로그램(펼치면 `…/seen`으로 `새 모집` 배지 해제)과 날짜 없는 활동.
- 푸시(FCM): `features/push`. **`app/google-services.json`이 있을 때만** `com.google.gms.google-services` 플러그인을 적용한다. 파일은 저장소에 넣지 않고(`apps/android/.gitignore`) `~/.dearby-deploy/google-services.json`에 두었다가 푸시를 받을 빌드 전에 `apps/android/app/`로 복사한다. 없으면 Firebase가 초기화되지 않고 앱은 푸시 없이 동작한다(CI·로컬 빌드). Firebase 콘솔에서 Android 앱 `io.wid.dearby`를 등록해 받은 파일이며, 서버 발송 자격(FCM HTTP v1 서비스 계정)은 운영 `.env.prod`에만 둔다. CI(`native.yml`)와 Play 출시(`android-play-release.yml`)는 저장소 시크릿 `ANDROID_GOOGLE_SERVICES_JSON`(파일 내용 그대로)이 있으면 빌드 전에 이 파일로 쓰고, 없으면 푸시 없이 빌드한다. Firebase는 `firebase-messaging`과 `firebase-analytics`만 쓴다(크래시리틱스 등 없음). BoM은 35.1.0(2026-10-25 Kotlin 2.4.21로 올려 35.x analytics의 Kotlin 2.4 메타데이터를 읽는다). Messaging 26은 토큰 API(`getToken`·`onNewToken`)를 설치 ID 등록으로 대체하며 사용 중단 표시했지만 서버가 FCM 토큰으로 보내므로 그대로 쓴다(`Push.kt`의 억제 주석). 매니페스트 `firebase_messaging_auto_init_enabled=false`.
- 푸시는 처음 프로그램 하트를 누를 때 시작한다: 그때 FCM 자동 초기화를 켜 토큰을 만들고(그 전에는 토큰이 없다), Android 13+에서는 알림 권한을 이때 한 번만 묻는다(앱 시작 때 묻지 않음). 시작한 뒤 로그인 상태에서 `새 모집 알림`이 켜져 있으면 시작·로그인·새 토큰·시간대 변경·권한 허용 때 `PUT /v1/me/push-devices {platform, token, timeZone}`, 로그아웃·알림 끄기 때 `DELETE`. 채널 `new_recruitment`(`새 모집`). 알림을 누르면 `data.url`(`/activities/{id}` App Link 또는 `dearby://favorites?view=calendar`)을 연다. 프로필 `알림` 묶음의 `새 모집 알림`은 `/v1/me/notification-settings`이고, 시스템 알림이 꺼져 있으면 설정 열기 줄이 붙는다.

## 사용 통계 (2026-10-25)

사용자 결정 "Analytics SDK 넣어줘". `features/analytics/Analytics`가 Firebase Analytics를 감싼다(google-services.json이 없으면 아무것도 하지 않음).

- 개인정보 최소: 매니페스트 `google_analytics_adid_collection_enabled`·`google_analytics_ssaid_collection_enabled`·`google_analytics_default_allow_ad_personalization_signals`를 모두 false, 병합되는 `ACCESS_ADSERVICES_AD_ID`·`ACCESS_ADSERVICES_ATTRIBUTION`·`ACCESS_ADSERVICES_TOPICS` 권한은 `tools:node="remove"`. `AD_ID` 권한은 2026-10-25부터 대기열 끝 광고(AdMob)용으로 남기며, 사용 통계는 여전히 광고 ID를 모으지 않는다. 사용자 id·개인정보를 넣지 않는다.
- 남기는 것: 이벤트 사전 [analytics-v1](../../shared/contracts/analytics-v1.md) 그대로. 사용자 속성 `interest_fields`·`interest_kinds`·`has_eligibility`(yes/no만)·`signed_in`(`app/Tracking`, 추천 설정을 읽거나 저장할 때·로그인·로그아웃 때), 퍼널(`funnel_start/step/skip/later/complete/exit`, `RecommendationViewModel`), 대기열 도달(`queue_open/card_view(1초)/card_complete/like/dismiss/detail/end/exit`, `QueueViewModel`), 전환(`activity_view`(source)·`favorite_add/remove`·`notify_level_set`·`myactivity_add`·`apply_click`·`push_open`), 메뉴 접근(`tab_select`·`menu_open`), `screen_view`의 화면 이름(`discovery`·`activity_detail`·`queue`·`favorites`·`my_activity`·`profile`·`notifications_inbox` 등). `field`는 활동 첫 분야 태그의 상위 분야 nameEn(공개 태그 사전으로 찾음), `category`는 활동 종류 코드 소문자. 매개변수는 id와 코드뿐이다.
- GA 콘솔(사용자): 맞춤 측정기준으로 사용자 범위 `interest_fields`·`interest_kinds`·`has_eligibility`·`signed_in`, 이벤트 범위 `step`·`entry`·`tab`·`menu`·`position`·`field`·`category`·`source`·`type`·`level`·`kind`·`reason`을 등록한다(등록 전 데이터는 보고서에 쓸 수 없다).
- 내 프로필 `사용 통계 보내기` 스위치(기본 켬, 로그인과 무관): `setAnalyticsCollectionEnabled`, 선택은 `app/DevicePreferences`(`dearby.favorites` 파일)에 둔다.
- 개인정보처리방침에 Firebase Analytics(Google, 앱 인스턴스 id, 사용 이벤트, 국외 이전)를 적어야 한다.
- 확인: `adb shell setprop debug.firebase.analytics.app io.wid.dearby` 뒤 `adb logcat -s FA FA-SVC`.

- 처음 저장하기 전(`version` 0) 프로필 화면은 토스식 아코디언 퍼널(`ProfileSetupPage`, 2026-10-17 결정)이다: 이름 → 직무(선택) → 전화번호 → 이메일 → 소개(선택) 섹션이 순서대로 쌓이고, 열린 섹션은 하나뿐이며 답한 섹션은 56dp 행으로 접혀 탭하면 다시 열린다. 질문 `headlineMedium`(24sp 굵게), 입력은 기본 크기 `OutlinedTextField`(아래 "폼은 플랫폼 기본 컴포넌트"), 좌우 24dp, 하단 `DearbyButton`("다음" → 모두 답하면 "프로필 저장"). 퍼널 동안 하단 탭바를 숨긴다(`DearbyApp`, `ProfileViewState.settingUp`). 섹션 상태는 `remember`라 회전하면 첫 질문으로 돌아간다(입력값은 VM에 남는다). 저장되면 인라인 편집기로 바뀐다. 프로필 없이 명함 만들기를 열면 안내만 보여 준다.
- 직무(계약 "직무", 2026-10-17): 직함 문자열 대신 `jobs` 태그. `JobTagPicker`(widgets/profile/profileFields)가 `GET /v1/jobs` 검색 결과(`ProfileViewModel.searchJobs`, 300ms 디바운스)를 `InputChip`으로 여러 개(10개) 고르고, 없으면 직접 적는다(시계 아이콘 = 승인 대기). 퍼널의 직무 섹션과 편집기의 "직무" 항목이 같은 위젯을 쓴다. 명함·버전 화면의 `job`은 서버가 승인된 이름을 이어 준 문자열 그대로다.
- 이력은 단계별 입력(`HistoryFunnelPage`): 조직/활동 → 조직 → 프로그램 → (활동) → 역할 → 기간 → 설명 → 확인. 각 단계는 `ActivityInfoPicker`로 등록된 활동 정보를 검색(`GET /v1/organizations|programs|activities|roles`, 300ms 디바운스)하거나 그대로 적는다(직접 입력 = 승인 대기). 인증자료(`EvidenceFields`)는 저장된 이력에서 사진·PDF를 3개까지 올린다(파일 고르기는 `ProfileRoute`). `verified`가 아니면 "미확인".
- 명함 만들기(`CardComposerRoute`): 명함 이름을 적고 공개할 연락처·이력을 고른다. 본문은 프로필 자기소개 그대로이고 제작 화면은 그것을 읽기 전용 "미리보기"(`MarkdownBody`)로 보인다. 발행·고치기 요청에 `template`을 보내지 않고 서버가 자기소개를 복사한다(2026-10-26 템플릿 폐지: 템플릿 정규식이 Android 17 ICU에서 `PatternSyntaxException`으로 명함 만들기를 열자마자 앱을 끝냈다). 미승인 이력은 선택 불가. 내용이 바뀌면 "원래대로"가 나타난다.
- 폼은 플랫폼 기본 컴포넌트(2026-10-19 밤, 계약 같은 이름; 사용자 "높이나 폰트가 앱에서 누르기는 힘들어 보여"): 직접 만든 입력 컨트롤(`shared/ui/Controls.kt`의 밑줄형 `DearbyInlineField`·둥근 `DearbySearchField`, 디버그 `ControlsPreview`)을 지우고 Material 3 기본 컴포넌트를 기본 크기 그대로 쓴다. 사용자 정의 높이·글자 크기는 없다. `shared/ui/Motion.kt`의 `rememberReduceMotion`만 남았다.
  - 글 입력(프로필 퍼널·프로필 편집의 이름·소개, 연락처의 전화번호·이메일·추가 연락처, 이력 퍼널의 설명, 명함 만들기의 명함 이름): `OutlinedTextField`(56dp, `bodyLarge`)에 항상 보이는 `label`, 예시는 `placeholder`, 필수·도움말·오류 문장은 `supportingText`(필수는 라벨의 `*`가 아니라 "필수예요." 문장)와 `isError`. 여러 줄(소개·설명)은 `minLines = 3`. 키보드 종류·`imeAction`·`KeyboardActions`(퍼널의 다음)와 `focusRequester`는 그대로다. 접근성 이름은 라벨뿐이다(라벨과 겹치던 `contentDescription`은 뺐고, 날짜 버튼의 `시작일, 필수, <날짜>`·삭제 아이콘처럼 정보를 더하는 것만 남겼다). 추가 연락처의 삭제는 칸의 `trailingIcon`, `연락처 추가`는 `DearbyOutlineButton`, 종류 고르기 시트는 `ListItem` 줄(이름 + 안내 문구).
  - 검색 칸: 직무 선택(`JobTagPicker`)과 이력 선택 창(`ActivityInfoPicker`)은 같은 slice의 `PickerSearchField`(돋보기 `leadingIcon`·지우기 `trailingIcon`을 둔 `OutlinedTextField`, 라벨이 접근성 이름). 받은 명함 검색은 `SearchBarDefaults.InputField`(56dp 둥근 바탕, 계약의 검색창 모양). 발견 탭 검색창은 `pages/activity/ActivityListPage.kt`가 따로 그린다(2026-10-19 밤 "발견 탭 스크롤 동작").
  - 날짜(이력 기간): 읽기 전용 `OutlinedTextField`(달력 `trailingIcon`, 투명 덮개가 탭을 받아 포커스되지 않음, 전체가 하나의 버튼으로 읽힘)를 누르면 기존 `DatePickerDialog`. 스위치·체크박스(`진행 중`, 명함 만들기의 공개 토글, 동의 화면의 두 항목)는 `ListItem` 안의 `Switch`/`Checkbox`로 줄 전체가 토글이다.
  - 키보드 내리기(계약 같은 절, 사용자 "키보드가 올라왔을 때 폼을 제외한 다른 곳 클릭 시 내려가게"): 입력 화면 루트(`ProfilePage`(퍼널 포함)·`HistoryFunnelPage`·`CardComposer`·`WalletPage`)에 `shared/ui/Keyboard.kt`의 `Modifier.dismissKeyboardOnTap()`(`pointerInput` + `detectTapGestures`로 빈 곳 탭 때 `LocalFocusManager.clearFocus()`; 필드·버튼은 자기 탭을 먼저 소비해 영향 없음)을, 스크롤 컨테이너(`verticalScroll` Column·`LazyColumn`)에 `imeNestedScroll()`을 둔다. IME 인셋은 `DearbyApp` 셸 Column이 `statusBarsPadding().navigationBarsPadding().imePadding()`으로 한 번만 적용하고(페이지에는 `imePadding` 없음 — 페이지마다 두면 탭 막대 높이만큼 띠가 남았다), 키보드가 올라와 있는 동안(`WindowInsets.isImeVisible`) 하단 탭 막대를 숨긴다. `AndroidManifest`의 `MainActivity`에 `windowSoftInputMode="adjustResize"`를 두어 API 26–29에서도 `enableEdgeToEdge()`와 함께 IME 인셋이 전달된다. 발견 검색창은 `ActivityListPage`가 맡는다.
