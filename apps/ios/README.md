- 코드: `entities/account/api/AppleSignIn.swift`(OS 요청, scope 이름·이메일, 서버 nonce를 해시하지 않고 그대로 넣음), `AccountClient`(`/v1/auth/apple/nonce`·`/auth/apple`·`/auth/apple/register`·`/me/identities/apple`), `AccountViewModel`, `SignInSheet`·`IntroPage`, 버튼 `shared/ui/DearbyAppleButton.swift`.

- **켜짐(2026-10-16)**: 두 entitlements에 `com.apple.developer.applesignin` = `["Default"]`, 두 Info.plist의 `DearbyAppleSignInEnabled` = `true`. App Store profile은 Sign in with Apple 포함으로 다시 만들어 `IOS_APPSTORE_PROFILE_BASE64`에 넣었다(2026-10-16 13:45 UTC). 기기 Debug 빌드는 `io.wid.dearby` 앱 ID에도 이 기능이 켜져 있어야 서명된다.
- 끄려면 두 값을 되돌린다. entitlement만 남기고 플래그를 끄면 버튼만 숨는다.
- 실제 애플 로그인은 entitlement가 있는 서명 빌드와 운영 API(`APPLE_CLIENT_IDS` 설정)에서만 확인할 수 있다. entitlement 없이 요청하면 OS가 실패로 돌려준다.

CI는 값 없이 빌드하며 버튼이 숨겨진다. 값은 저장소·채팅에 적지 않는다.
- 켜짐 판단: `googleSignInEnabled`는 빌드에 `GIDClientID`가 있으면 참으로 시작하고, `auth/google/nonce`가 503(`AccountError.disabled`, 서버에 `GOOGLE_CLIENT_IDS` 미설정)을 돌려주면 그 실행 동안 버튼을 숨기고 "지금은 구글 로그인을 쓸 수 없어요."를 보인다. 네트워크 실패·5xx(`unavailable`)는 버튼을 숨기지 않는다.
- 버튼: `secondarySystemGroupedBackground` 바탕·`line`(`separator`) 테두리·높이 50·모서리 11에 "Google로 계속하기". 앞의 "G"는 공식 로고 파일을 `shared/assets/prototype`에 받아 넣기 전까지의 글자 자리표시다. `SignInSheet`와 `IntroPage`에서 애플 버튼 아래에 보인다.
- 흐름: 이미 연결된 구글 계정(200)은 바로 로그인한다. 처음 보는 계정(202)은 애플과 같은 `linkOrStart`를 탄다(이 기기의 Dearby 패스키를 조용히 묻고, 있으면 연결·없으면 새 계정, 시트를 닫았을 때만 "처음 보는 구글 계정이에요" 선택 화면). 애플·구글이 같은 `AccountViewModel.PendingLink`를 쓴다. 구글 계정 시트를 닫으면 문구 없이 끝난다.
- 서버 쪽 필요 조건(앱 밖): 운영 API의 `GOOGLE_CLIENT_IDS`에 웹 클라이언트 id와 iOS 클라이언트 id(SDK가 만든 ID 토큰의 `aud`는 iOS 클라이언트 id다). 없으면 버튼이 숨겨진다. 실기기에서만 확인할 수 있다.

## 계정 삭제 (2026-10-16)

계약 `shared/contracts/native-v1.md` "계정 삭제"(App Store 5.1.1(v))를 따른다. 애플 로그인 플래그와 관계없이 보인다.

- 위치: 내 프로필 탭 맨 아래 "계정 삭제"(로그인 상태, 프로필을 불러오지 못한 화면에도). 앱에는 아직 로그아웃 버튼이 없다.
- 확인 창("계정을 삭제할까요?", 삭제/취소) 뒤 `DELETE /v1/me`. 다른 로그인 호출처럼 401이면 refresh를 한 번 하고, refresh가 거절되면 로그아웃 상태로 돌아가 "로그인이 만료됐어요"를 보인다. 요청 중에는 버튼을 막아 한 번에 하나만 보낸다.
- 204: Keychain 토큰을 지우고(서버가 refresh token을 이미 지워 `/auth/logout`은 부르지 않음) 로그아웃 상태로 돌아가 "계정을 삭제했어요. 기기에 남은 패스키는 설정 > 암호에서 지울 수 있어요."를 한 번 보인다. 받은 명함·내 명함 탭의 메모리 데이터는 로그아웃 상태로 다시 불러올 때 비운다.
- 실패: "계정을 삭제하지 못했어요. 잠시 후 다시 시도해 주세요."를 보이고 로그인을 유지한다.

## 프로필·명함 v2 (2026-10-17)

계약 `native-v1.md` "프로필·명함 v2". 2026-10-17 사용자 결정으로 유비쿼터스 언어는 "활동"이다(코드에서 조직·프로그램·활동·역할을 아우르는 이름은 `ActivityInfo`).

- 내 프로필(`ProfilePage`)은 데이터 입력만 한다. 시스템 내비게이션 바(변경 이력 `clock`·명함 만들기 `person.text.rectangle` 아이콘 버튼, 설정·알림) 아래 inset-grouped `Form`(기본 정보·직무·소개·연락처·활동 이력·계정 삭제 섹션)에서 칸을 바로 고치고, 불러온 프로필과 달라지면 아래에 "저장"·"원래대로" 막대가 나타난다(`ProfileForm.changed`). 저장은 `If-Match: <version>`을 보내고 409면 다시 불러오라고 안내한다. "변경 이력"(`ProfileVersionsPage`)에서 저장한 버전을 보고 되돌린다(새 버전으로 저장).
- 개인정보 동의(`ConsentPage`, 2026-10-19 계약 "개인정보 동의"): `GET /v1/profile`의 `consentRequired`가 참이거나 저장이 403 `CONSENT_REQUIRED`를 돌려주면 프로필 탭 전체가 동의 화면이 된다(탭 바 숨김). 필수 스위치(`Toggle`) 두 개와 그 아래 `…보기` 행은 웹 `/privacy`·`/terms`를 `SFSafariViewController`로 열고, 둘 다 켜야 `동의하고 계속`이 켜지며 `POST /v1/me/consents`(버전은 `ConsentVersions`, 2026-10-19) 뒤 프로필을 다시 불러온다. 로그아웃 상태에서는 보이지 않는다.
- 처음 저장하기 전(`version` 0) 프로필 탭은 아코디언 퍼널(`ProfileFunnelPage`, 2026-10-17 결정)이다: 이름 → 직무(선택) → 전화번호 → 이메일 → 소개(선택) 단계가 순서대로 쌓이고, 열린 단계는 하나뿐이며 답한 단계는 `LabeledContent` 행으로 접혀 탭하면 다시 열린다. 열린 단계는 inset-grouped `Form`의 한 섹션으로, 질문이 섹션 header(`.title3` 굵게), 도움말·오류가 footer이고 입력은 시스템 `TextField`(`.body`)다. 단계가 열리면 키보드가 바로 뜬다. 하단 버튼은 `.borderedProminent` + `.controlSize(.large)`("다음" → 모두 답하면 "프로필 저장"). 퍼널 동안 탭바를 숨긴다(`HomePage.hidesTabs`). 저장되면 인라인 편집기로 바뀐다. 프로필 없이 명함 만들기를 열면 안내만 보여 준다.
- 직무(계약 "직무", 2026-10-17): 직함 문자열 대신 `jobs` 태그. `JobTagPicker`가 `GET /v1/jobs`를 검색해 칩으로 여러 개(10개) 고르고, 없으면 직접 적는다(시계 아이콘 = 승인 대기, 승인 전에는 명함 `job`에 안 들어감). 퍼널의 직무 섹션과 편집기의 "직무" 항목이 같은 위젯을 쓴다. 명함·버전 화면의 `job`은 서버가 승인된 이름을 이어 준 문자열 그대로다.
- 폼은 플랫폼 기본 컴포넌트(계약 "폼은 플랫폼 기본 컴포넌트 — 2026-10-19 밤"): 입력 화면(프로필 퍼널·편집기, 이력 퍼널, 명함 만들기, 연락처 추가, 직무 선택, 동의)은 `Form` + inset-grouped `Section`이고 행은 `TextField`·`Toggle`·`DatePicker`·`LabeledContent` 그대로다(행 높이는 시스템 최소 44). 라벨은 `LabeledContent` 라벨 또는 한 칸짜리 섹션의 header로 항상 보이고, 필수는 footer 문장으로 알린다. 글꼴은 `Form`에 `.dearby(.body)`(Pretendard 17)를 두고 header·footer는 `.dearby(.footnote)`를 명시한다. 오류는 footer의 `DearbyFieldError`(`.footnote` 빨강 + 아이콘). 주 버튼은 `.borderedProminent`, 보조 버튼은 `.bordered`, 모두 `.controlSize(.large)`(높이 50)이며 하단 막대는 `.safeAreaInset(edge: .bottom)` + `.bar` 배경. 직무·활동 정보 검색은 섹션 안에 `DearbySearchField` 행(배경 투명)을 둔다. 키보드 내리기(계약 "키보드 내리기"): 글자 입력이 있는 화면 루트(프로필 퍼널·편집기, 이력 퍼널, 명함 만들기)에 `shared/ui`의 `.dearbyDismissKeyboard()`를 달아 스크롤로 내리고(`.scrollDismissesKeyboard(.interactively)`) 빈 곳 탭이 첫 응답자를 내린다(배경 전용 `onTapGesture`, 버튼·필드 탭은 그대로). 발견 검색창은 발견 페이지 담당. 옛 밑줄형 `DearbyInlineField`는 지웠다. 같은 날 후속으로 활동 상세·신청 확인·캘린더 겹침·내 명함·받은 명함·변경 이력의 버튼도 시스템 스타일로 바꾸고 `DearbyButtonStyle`을 지웠다(앱 루트 `.tint(DearbyStyle.teal)`로 시트도 청록).
- 이력은 단계별 입력(`HistoryFunnelPage`): 조직/활동 → 조직 → 프로그램 → (활동) → 역할 → 기간 → 설명 → 확인. 각 단계는 `Form` 섹션이고(질문 = header, 오류 = footer) `ActivityInfoPickerView`로 등록된 활동 정보를 검색하거나(`GET /v1/organizations|programs|activities|roles`) 그대로 적는다(직접 입력 = 관리자 승인 대기, `approval`). 기간은 `DatePicker`·`Toggle` 행(`HistoryPeriodFields`), 설명은 `TextField(axis: .vertical)`. 인증자료(`EvidenceSection`)는 저장된 이력에서 사진·PDF를 3개까지 행으로 올리고(왼쪽으로 밀어 삭제), `verified`가 아니면 "미확인" 배지가 붙는다.
- 명함 만들기(`CardComposerPage`): `Form`에서 명함 이름(선택)과 공개할 연락처·이력(`Toggle` 행)만 고른다. 본문은 앱 내장 기본 템플릿(`TemplateDocument.starter`: `{{profile.name}}`·`{{profile.job}}`·`{{profile.introduction}}`·전화·이메일 `{{contact:<id>}}`)이고 화면에는 채운 결과를 읽기 전용 미리보기(`DearbyMarkdownText`)로 보인다. 서버가 발행할 때 채운다(`POST /v1/cards {template}`). 템플릿에 든 연락처는 자동으로 공개되고, 승인되지 않은 이력은 고를 수 없다. 이름·선택이 바뀌면 "원래대로"가 나타나며, 내 명함 탭의 "이 명함 고치기"는 그 명함의 이름·선택으로 새 명함을 발행한다. 2026-10-18 사용자 결정으로 앱 안 꾸미기(렌더링 화면 편집기 `TemplateEditor`, 데이터 넣기)와 같은 날 추가한 웹 버전 스위치를 지웠다(계약 "템플릿 — 2026-10-18 앱 안 꾸미기 삭제").
- 오류는 ProblemDetail의 `detail`(`AccountError.rejected`)을 그대로 보인다.
- 확인하지 못한 것: 실제 서버·기기에서의 흐름(시뮬레이터 대상 빌드만 통과).
