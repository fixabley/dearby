# Saved organization list composition

FavoriteOrganizationListViewModel in widgets/favoriteOrganizationCard/model owns the visible cards and load failure for one snapshot. It builds organization ID → feed notice IDs once, then constructs only saved organizations in manifest order. Each organization card receives only its indexed feed IDs. Unsaved organization/path failures no longer fail feed startup; this does not hide failures of organizations actually required by a feed card.

The source of saved IDs remains the single FavoriteOrganizationStore behind FavoriteOrganizations. The Feature action facade publishes synchronous post-mutation notifications only for changed IDs. Its weak subscription token does not retain the list; releasing a token ends observation. Reentrant changes are drained after the current notification, without recursive callbacks. Repeated saves retain existing card instances and do not repeat repository work.

AppSnapshotComposition creates the candidate list inside the existing snapshot transaction. Any required saved-card construction/save failure preserves the old manifest, L2, repositories and list. AppState detaches the old list and activates the new subscription only after commit. There is no async gap, body I/O or separate mutable saved-ID list.

New saves/removals update the visible list synchronously, so cards and open detail still read the same saved IDs immediately. The list reuses existing cards and loads only newly visible ones. A new-card read failure keeps the saved action and existing visible cards, exposes a brief failure/retry in the Page, and retries only via an explicit action or a later saved-ID change. Failure is not silently presented as an empty collection. An organization with no linked feed notices still appears with its existing empty-row presentation.

`run_standalone.sh` covers the production AppState/list path: unsaved failures, index/row membership, add/remove and open-detail consistency, repeated reads and duplicate saves without I/O, explicit retry, candidate failure preservation, old subscription detachment, weak lifetime and nonrecursive notifications. Simulator compilation is separate from real UI interaction.
