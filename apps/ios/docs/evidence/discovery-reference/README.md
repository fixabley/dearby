# 승인 시안 적용 — 2026-09-29 iOS

사용자 요청: 현재 상태 커밋 후 이전 렌더링을 참고해 실제 시뮬레이터 화면에 적용. 변경 전 체크포인트5b837bd, 현재 작업 feat/conference-mock-data. 이번 범위는 사용자가 보고 있는 iPhone17의 탐색/상세/신청/캘린더 진입이다. Android 화면은 이번 시각 수정에 포함하지 않았다.

[비교 갤러리](comparison.html), 기준은 docs/design/approved/discovery.png 및 activity-detail-top/schedule/bottom.png. 숨긴 탭/저장/알림을 되살리지 않으며 신청 Safari와 권한 시트의 OS 외형은 유지한다.

## 변경

- 좌측 이미지와 우측 제목·설명·일시, 20pt 바깥 여백과 흰 카드·청록 강조 유지. 공식 이미지4개를 목 서버에 연결하고 같은 ActivityArtwork를 목록/상세에서 재사용했다. 알려진 이미지 없는 실제 항목은 자리표시자, 가상 활동은 데모 표식. 이미지 비율/글자를 자르지 않도록 contain 처리.
- 상세는 큰 대표 이미지, 예시/참가 유형, 제목·조직, 아이콘/항목명/값의 정렬. 고정 하단 CTA 보존.
- 행사 일정을 시각·점·연결선·제목·날짜/시간대의 세로 타임라인으로 표시. 미확인 시간은 미정 유지. 캘린더 버튼을 일정 아래 전체 너비 테두리 버튼으로 이동. 이전 ‘비교 미제공’ 문구 삭제.
- 선택적 imageUrl/isPreview DTO 필드 추가. 이전 payload/cache와 호환, Android는 unknown key를 무시한다. 운영 API/수집기는 변경하지 않으며 목 서버가 신규 필드를 제공한다. 구형 클라이언트를 위해 실제 JSON 제목에는 목 접두사를 보존하고 iOS만 예시 배지와 간결한 제목으로 표시한다.
- iOS 글자 크기에 따라 정보 행이 세로 배치로 바뀌고 탐색 썸네일을 접는다. 제목/버튼 글자를 강제로 축소하지 않는다.

## 실행 증거

- 변경 전 실제 UI flow1pass와 before 캡처, 변경 후 실제 UI4pass(탐색 기본 노출, 상세→캘린더→신청→나중에, 큰 글자, 공식 이미지 상세).
- 단위41 중32pass/9 명시적 조건부 skip. 기존 API 전용 기대값(if(kakao)26)이 목 응답 첫 행사와 달라 통합 실행1건 실패했다. 테스트를 약화하지 않고 일반 단위를 API URL 없이 분리해 통과시켰다. 실패 실행은 종료 후 진단 수집이 지연돼 중단했으며 후속 단독 테스트는 정상 종료했다.
- 마지막 툴바 색상 수정 시 SwiftUI 타입 추론 오류는 명시적 ToolbarItem 배치로 해결했고 최종 실제 UI2건을 재실행해 통과했다.
- 구조16pass, strict SwiftLint64파일0위반, 최종 Simulator build/install/launch 성공. 선택적 메타데이터 누락/추가 payload의 역호환 회귀 포함. 목 서버6건/공식 이미지4개 HTTP200 확인.
- 캡처는 이번 iPhone17 실제 실행이며 공식 모집 검증이나 외부 신청 제출 증거가 아니다. 기존 임시 데모 캘린더2건은 보존했다.
- Ponytail: SwiftUI AsyncImage/기존 버튼 스타일/공유 이미지뷰만 사용. 추가 의존성·테마 엔진·범용 추상화 없음. Lean already. Ship.

## 남은 차이

원본은 가상 행사 사진과 예시 값이며 현재는 실제 공식 OG 아트와 목 데이터다. OG 글자를 자르지 않아 목록에서 여백이 생길 수 있다. 원본의 콘텐츠 분류/저장/알림/탭은 현재 승인 범위와 다르므로 되살리지 않았다. 이 작업 당시 캘린더 비교 시안은 확인되지 않았다. 이후 사용자 제공 폴더에서 찾은 시안 A를 명시적으로 선택받아 [별도 적용](../calendar-reference-a/README.md)했다. 작은 기기 별도 실행·VoiceOver 음성 탐색·실기기·Android 시각 동기화는 이번 검증에 포함하지 않는다.
