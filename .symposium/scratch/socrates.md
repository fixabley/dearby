## User Input

Dearby의 서비스 아이디어는 정해져 있으며, 기능·화면·사용 흐름을 구체화하고 싶다.

사용자 설명:
- 신규 조직·활동에 참여하고 싶은 사용자의 진입장벽을 줄이는 서비스다.
- 기존 구성원들과의 질의응답, 대면 커피챗으로 정보를 얻고 인맥의 물꼬를 틀 수 있다.
- 살아있는 정보를 얻을 수 있다.
- 제공자는 질문자가 만족도에 따라 사후 지불한 크레딧을 얻는다.
- 구체적 상황: 대외활동에 관심이 있지만 자신의 자격이 충분한지, 투자한 시간만큼 필요한 것을 얻을 수 있는지 몰라 망설인다.
- 인맥의 의미: 활동에 들어간 뒤에도 이어질 관계를 만든다.

## Cycle 1

### Wonder

- 참여 자격 판단 — 관심 있는 대외활동에 자신이 가진 자격이 충분한지 몰라 망설이는 상황을 해소한다.
- 시간 투자 가치 판단 — 활동에 시간을 투자했을 때 자신에게 필요한 것을 얻을 수 있는지 판단하도록 돕는다.
- 지속적인 관계 형성 — 기존 구성원과의 접점이 일회성 정보 획득을 넘어 활동 참여 이후에도 이어지는 관계가 된다.

질의응답·대면 커피챗과 만족도에 따른 사후 크레딧 지급은 사용자가 제시한 구상이다.
구체적인 운영 규칙과 성공 기준은 아직 정하지 않았다.

### Reflect

- 참여 자격 판단
  - User's intended nuance: 기존 구성원의 실제 경험에 비추어 자신의 경험·역량으로도 도전할 만한지 판단하고 싶다. 사용자 확인: "맞습니다".
  - Model's interpreted nuance: 공식 지원 조건 충족 여부보다 실제 참여자의 경험을 통한 준비 수준과 도전 가능성 판단이다.
  - Same / different: Same — 사용자 확인 완료.

- 시간 투자 가치 판단
  - User's intended nuance: 활동을 통해 얻고 싶은 결과는 "내가 관심있어하는 직군의 경험이나 정보"다.
  - Model's interpreted nuance: 실제 구성원의 경험을 듣고 해당 활동이 관심 직군의 경험이나 정보를 얻는 데 도움이 될지 판단한다.
  - Same / different: 사용자가 원하는 결과를 관심 직군의 경험·정보로 구체화했다.

- 지속적인 관계 형성
  - User's intended nuance: 활동에 들어간 뒤에도 관심 직군에 관해 계속 경험을 나누고 조언을 구할 수 있는 관계다. 사용자 확인: "맞습니다."
  - Model's interpreted nuance: 기존 구성원과의 만남이 활동 참여 이후에도 직군 관련 경험·조언을 나누는 지속적인 관계로 이어진다.
  - Same / different: Same — 사용자 확인 완료.

### Refine

초기 shared meaning(사용자 확인 완료): Dearby는 새로운 조직·활동에 관심 있는 사람이 기존 구성원과의 질의응답·대면 커피챗을 통해 자신의 준비 수준과 관심 직군의 경험·정보를 얻을 수 있는지를 판단하고, 참여 이후에도 경험과 조언을 나눌 관계를 만드는 서비스다.

사용자는 위 정의에 "맞아요"라고 확인하면서 다음 구상을 추가했다.
- 찾는 피로를 줄이기 위해 하루 한 번 추천 카드들을 제공한다.

추천 카드에 관해 사용자가 추가로 설명했다.
- 추천 대상은 대내·대외 활동이다.
- 활동 홍보자료를 크롤링으로 수집하고 간소화한다.
- 참여 자격과 사용자 관심사에 맞춰 추천한다.

추천 카드의 상호작용에 관해 사용자가 추가로 설명했다.
- 숏폼 콘텐츠처럼 "핑거 스냅으로 넘기고" 활동 카드를 탐색한다.
- "더블클릭으로 관심표시"를 할 수 있어야 한다. 모바일에서는 더블탭으로 해석했으며, 구체적인 제스처 방향은 미정이다.

관심 표시의 의미에 대한 사용자 답변:
- 관심 표시를 하면 해당 조직이 즐겨찾기처럼 목록으로 저장된다.
- 저장한 조직은 언제든 간편하게 확인할 수 있다.

추천 카드와 즐겨찾기의 관계를 사용자가 확인했다.
- 예: "SW마에스트로 13기 모집공고카드라면 SW마에스트로가 저장돼요."
- 개별 활동·모집공고는 추천 카드의 대상이며, 즐겨찾기 저장 단위는 해당 조직이다.
참여 자격이 불확실한 활동이 있다면 사용자에게 추가 정보 입력을 제안한다는 답변을 받았다.
입력 전 추천 노출 방식과 사용자가 입력을 건너뛸 때의 처리는 아직 정하지 않았다.
shared meaning: Dearby는 참여 자격과 관심사에 맞는 활동을 매일 간편하게 발견하고 관심 조직을 저장하며, 기존 구성원과의 질의응답·커피챗으로 참여 여부를 판단하고 지속적으로 경험과 조언을 나눌 관계를 만드는 서비스다.

확장된 정의에 대한 사용자 확인: "네 맞습니다."

앞서 언급된 크롤링·홍보자료 간소화, 하루 한 번 카드 제공, 카드 넘김·더블탭,
자격 불확실 시 추가 정보 입력 제안, 만족도에 따른 사후 크레딧 지급 구상은 유지한다.
크레딧 운영 규칙과 검증 가능한 성공 기준은 아직 미정이다.

### Reflect

- Meaning B — 경험 기반 맞춤 추천
  - User's intended nuance: “겹치는 게 있다면 제안해주되, 없다면 일치하는 태그만 강조해서 보여줘.”

사용자 추가 원문:

승인된 추가 요구: 사용자가 필터를 선택할 때 결과 개수를 제공한다. 비교 서비스의 구체 동작을 조사하거나 동일한 동작 전체를 채택한 것은 아니다.
확인할 의미: 결과 개수가 선택 조건을 모두 충족하는 활동만 뜻하는지, 부분 일치 추천까지 포함하는지. 모델 제안은 완전 일치 결과 개수와 부분 일치 추천 개수를 구분하여 표시하는 것이며 아직 사용자 승인 전이다.

사용자 결과 없음 처리 원문:
> 조건에 맞는 활동이 없을 경우, 결과가 존재하는 조합을 결과 수와 함꼐 알려줬으면 좋겠어.

결과 없음 처리의 최신 요구: 선택 조건에 맞는 활동이 없으면 결과가 존재하는 대체 조건 조합을 해당 결과 수와 함께 안내한다. 이전 모델 제안인 부분 일치 결과의 총개수만 표시하는 방식은 채택된 것으로 보지 않는다.
유지되는 승인: 직무만 일치하거나 경험만 일치하는 활동도 부분 일치 후보가 될 수 있다.
미확정: 대체 조합을 누르면 필터를 변경하여 결과를 보여줄지, 조합별 결과를 즉시 함께 보여줄지. 조건 제거와 대체 태그 제안 중 허용 범위, 조합 정렬·개수 제한·동일 그룹 복수 선택의 AND/OR는 아직 결정하지 않았다.

사용자 조합 범위 명확화 원문:
> 예를 들어 조건에 3개 선택됐을 경우, 그 중 결과가 있는 조합을 제안해주는거야

확정된 조합 의미: 사용자가 이미 선택한 조건들의 부분 조합 중 결과가 존재하는 조합을 찾아 각 결과 수와 함께 제안한다. 새로운 조건·태그를 추가하거나 유사 조건으로 교체하는 제안으로 해석하지 않는다. 3개는 예시이며 선택 개수 제한이 아니다.
예: A+B+C가 0개라면 선택 집합 안의 A+B, A+C, B+C 등의 조합에서 실제 결과가 있는 조합을 안내한다. 단일 조건 조합의 표시 여부, 제안 순서·개수, 조합 클릭 후 전환 방식은 아직 미확정이다.

사용자 확인: “좋아.” — 선택 조건 A·B·C의 전체 일치 결과가 없으면 기존 선택 조건의 부분 조합 중 결과가 있는 조합과 개수를 제안하고, 결과가 0개인 조합은 제안에서 제외하는 설명을 승인했다. 예시 숫자는 실제 데이터가 아니다.
다음 대화 주제: 수집할 대외활동의 의미와 범위. 교내 비교과·동아리·교육·채용 포함 여부는 아직 확정하지 않았다.

> ABC 모두 하되, 처음엔 교외활동 중심으로 해보려해

승인된 범위: 교외 활동(공모전·서포터즈·봉사·대외 프로젝트 등), 교내 활동(동아리·비교과·학과 행사 등), 직무 준비 기회(직무 교육·부트캠프·인턴 등)를 전체 제품 범위에 포함한다. 처음에는 교외 활동 중심으로 시작한다. “중심”을 교내 활동·직무 준비 기회의 영구 제외나 엄격한 수집 금지로 해석하지 않는다. 구체 수집 출처·초기 이용자 범위·확장 시점은 미정이다.
다음 확인: 초기 추천 대상 사용자를 대학생으로 한정할지, 취업 준비생·직장인 등까지 포함할지.

사용자 초기 이용자 범위 원문:
> ABC로 하되, 처음엔 A로 제공하고싶어

승인된 이용자 범위: 전체적으로 대학생·취업 준비생·직장인을 포함하되 처음에는 대학생에게 제공한다. 이후 대상 확장 시점, 가입 자격 제한·학생 인증 여부는 정하지 않았다. 활동은 초기 교외 활동 중심이라는 앞선 결정을 유지한다.

사용자 후속 기술 질문: “엘라스틱서치로 하면 RDB 필요없어?”
공식 문서 확인: Elasticsearch는 문서 저장소이므로 공고 중심의 단순 탐색 서비스는 RDB 없이 구성 가능하다. 관계형 모델을 그대로 복제하는 대신 비정규화를 권장하며 검색 반영에는 refresh가 관여한다. PostgreSQL은 관계 제약·트랜잭션이 필요한 원본 관리의 대안이다. 제안: ES를 채택하면서 사용자 선호의 서버 보존·운영 편집 등 관계·정합성이 필요한 범위까지 다루면 PostgreSQL을 원본으로, ES를 검색용 복사본으로 두는 구성을 고려한다. 단순 탐색 실험에서는 ES 단독도 선택 가능하다. 로그인·서버 즐겨찾기·병행 저장 구성을 새 요구사항으로 확정하지 않았고 기술 선택도 미결정이다.

모델 의견: 목적에 부합한다. 명시된 필수 자격의 미충족, 정보 부족으로 확인 필요, 우대사항을 구분하고, 이번 회차의 지원 가능 여부와 향후 준비 가능성을 혼동하지 않도록 제안한다. 이 세부 분류·표시 규칙은 미승인 제안이다.

- 자격 준비를 위한 스크랩은 지금 지원 의사와 다르므로 신호 의미를 분리한다.
- 명시한 최우선 경험과 현재 필터를 행동 이력이 임의로 덮어쓰지 않게 하고 추정 선호와 직접 선택을 분리한다.
- 노출된 프로그램만 반응을 얻는 편향을 고려하며, 노출 기록·제한적인 다양성·취소/초기화와 오래된 신호의 처리 등을 검토한다. 구체 저장/보관 규칙은 별도 합의 대상이다.
- 연속 점수의 미세한 차이 때문에 마감·최신성 순위가 사실상 적용되지 않을 수 있으므로 적합도 구간 등 대안을 검토한다. C→B→A 계약을 몰래 가중합 정렬로 바꾸지 않는다.
- 행동 기반 점수는 순위에 쓰고 필터 포함 여부·고유 프로그램 개수는 명시한 조건으로 계산하는 분리를 제안한다.

사용자 검색/추천 구분 의견 및 조언 요청:
> 검색일 땐 B인데 검색이 아니라 추천의 경우엔 A가 나아보이는데요.
> 제가 잘 몰라서 혹시 추천해줄 수 있나요?

사용자 의향: 검색은 선택한 방향 모두 일치(B), 추천은 하나라도 관련되면 후보에 포함하고 둘 다 관련되면 우대(A)가 적합해 보인다고 밝혔다. 최종 조언을 요청한 상태다.
모델 권고: 검색은 명시 필터를 모두 충족하는 프로그램과 그 개수를 표시하고, 0건이면 실제 결과가 있는 선택 조건의 부분 조합을 별도로 제안한다. 추천은 프로필을 관심 신호로 사용하여 부분 일치도 후보로 포함하고 일치한 이유를 표시한다. 방향 복수 일치는 다른 조건이 비슷할 때의 가점이며, 사용자가 지정한 최우선 경험과 모집 중 우선/C→B→A 정렬 계약을 임의로 뒤집지 않는다. 명시 검색 필터와 프로필 선호를 분리하며 추천 이력 때문에 검색의 포함 조건·개수를 바꾸지 않는 안을 제안한다.
UX 권고(미확정): 검색 필터에는 ‘선택한 태그 모두 포함’을 표시하고 프로필의 관심 태그를 검색 필터에 자동 강제하지 않는다. 부분 조합의 필터 적용은 사용자가 선택하도록 제안하되 앞서 클릭 전환 정책은 아직 확정되지 않았다.

사용자 검토 요구 및 수정안 승인:

모델은 검색 B/추천 A를 일괄 적용하자는 앞선 권고가 태그 선택 의도의 반례를 충분히 검토하지 않았음을 인정하고 수정안을 제시했다.

최신 승인 검색 기본값:
- 방향 태그 여러 개는 하나라도 관련되면 포함(OR)한다.
- 방향과 경험이라는 서로 다른 유형은 함께 충족(AND)한다.
- 특정 방향들을 반드시 함께 원하면 ‘모두 포함’을 선택할 수 있다. 구체 조작 위치는 미정이다.
- 추천은 일부 일치도 후보에 포함하고 선호에 따라 순위를 정한다.

위 수정안은 앞선 검색 전체 AND 권고보다 우선한다. 경험 태그를 여러 개 선택한 경우의 기본 AND/OR는 수정안 표에서 정하지 않았으므로 별도 확인한다. 결과 0건의 부분 조합 제안은 현재 검색 조건식의 의미에 맞춰야 하며, 원래 필터를 몰래 변경하지 않는 구상은 유지한다.
